# VI — правила для агентов

## Модели

- **Fable** — только обсуждение и планирование, когда пользователь сам открыл такую сессию. Код на Fable не пишем, субагентов и workflow на Fable не запускаем.
- **Opus** — основная работа: реализация по спекам и планам, ревью.
- **Sonnet** — багфиксы и мелкие механические правки; поиск и чтение кода.

При запуске субагента или workflow всегда указывать `model` явно: `opus` для реализации, `sonnet` для багфикса, механики и поиска. Без параметра субагент наследует модель сессии, и в сессии Fable это самый дорогой вариант.

Спеки и планы пишутся так, чтобы исполнитель не изучал проект заново: точные пути файлов, интерфейсы, порядок шагов, команды проверки. Исполнитель читает план и названные в нём файлы, а не весь репозиторий.

## Работа

- `src/rules` — чистая детерминированная симуляция. Визуал, звук и интерфейс читают её состояние и события и никогда не влияют на правила.
- Визуальный стиль ведёт пользователь. Агент исполняет принесённый им слой и не придумывает внешний вид по своей инициативе.
- Весь интерфейс игрока — один слой: рисуется в канвасе через `src/shell`, цвета, шрифты и размеры берёт только из `src/shell/theme.ts`. Новый DOM-интерфейс не заводим; новый элемент интерфейса добавляется вместе со строкой в [VI_Interface_Layer.md](docs/art/VI_Interface_Layer.md).
- Проверка: `npm test`, `npm run typecheck`, `npm run build`. Дев-сервер — только через preview (`vi-dev` в `.claude/launch.json`, порт 5183).
- Работаем в `main`. Коммит и пуш — только после «ок» пользователя: пуш в `main` публикует сборку на GitHub Pages.
- Основная папка `GAMES\VI` — рабочее место одного чата: того, который пользователь открыл на ней (с 5 октября 2026 это чат вида игры). Все остальные чаты работают в своих worktree и в основную папку ничего не пишут и не копируют — ни файлы, ни сборки, ни «для проверки».
- Публикация из worktree: `git fetch`, перенести свою работу на `origin/main` (rebase), прогнать проверки, `git push origin HEAD:main` — после «ок» пользователя.
- После любого пуша в `main` основная папка подтягивается `git pull --ff-only`: это делает её чат, когда начинает работу, и перед своим коммитом. Если pull не проходит, потому что в папке лежит чужое, — не чинить силой (`reset --hard`, `stash`, `checkout --`), а сказать пользователю.
- Принятую пользователем правку не держать незакоммиченной: спросить «коммит?» сразу. Незакоммиченные файлы — то, из-за чего папку нельзя подтянуть.
- Если в рабочем дереве всё же лежат чужие незакоммиченные правки — в коммит брать только свои файлы, без `git add -A`.
