## Задача 3. Статус и проверка по коду

Словарь статусов (только эти слова):

- `в силе` — для истины и решений, которым ничего не противоречит;
- `построено` — решение воплощено; указать версию из `package.json` коммита и короткий хеш (найти по `git log --all --oneline -- <пути из спеки>` и по сообщениям коммитов: в этом репозитории они длинные и описывают сделанное);
- `вытеснено: <путь>` — другой документ отменил или заменил; указать какой;
- `отменено` — владелец отказался (искать в ROADMAP, в поздних документах, в сообщениях коммитов);
- `черновик` — владелец не читал или не утверждал;
- `выполнен` / `не выполнен` — для планов.

Как проверять «живёт в коде»:

- [ ] Из документа выписать упомянутые пути (`src/...`, `scripts/...`, `public/...`), адресные флаги (`?lab=`, `?levels`, `?perf`, `?gates=off` и т. п.), имена функций и констант.
- [ ] Для каждого пути: `test -f`. Для флагов и имён: `grep -rn` по `src/` и `scripts/`. Записать: сколько упомянутого существует, что не существует (перечислить).
- [ ] Для спеки с «решениями» (разделы вроде «Решено», «Принято», пронумерованные правила): проверить три-четыре ключевых решения по коду и записать: подтверждено / не найдено / сделано иначе (с указанием файла и строки, где иначе).

Образец шапки, в вокабуляре которой писать предложения (саму шапку в документы НЕ вставлять, это шаг 3):

