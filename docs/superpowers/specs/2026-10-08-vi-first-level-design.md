## 1. Цель

Новый игрок запускает игру, за минуту понимает управление и первые два правила, проходит четыре короткие задачи подряд и, не выходя ни в какое меню, оказывается на следующем уровне. Слова владельца: «новый игрок запускает игру, понимает базовое управление, проходит несколько задач и сам хочет следующую».

Чему учит уровень, без единого слова:

1. свайп (на клавиатуре — стрелка) катит куб на соседнюю клетку;
2. перекат меняет верхнюю грань: грань, которую видишь сбоку, поднимается наверх, когда катишь от себя или влево;
3. комбо — столько костей, сколько точек на грани, рядом по стороне: две двойки, три тройки; оно уходит под пол.

Чего уровень не вводит: толчок, цепочку, единицы, пол как дорогу, предел ходов, звёзды.

## 3. Вход в игру

### 3.1. Boot

Как сейчас (`src/shell/screens/boot.ts`, `bootScript.ts`): длинный при первом запуске устройства, короткий потом. Сейчас boot уже пропускается любым нажатием или клавишей (`skip` в `src/shell/input.ts`), но игрок этого не знает. Новое — кнопка **скип** в правом нижнем углу, маленькая, из деталей слоя (строка-команда `SKIP` в языке игрока, с меткой седьмого); нажатие на неё делает то же, что любое нажатие. На коротком boot её нет. Вид — за владельцем; до его слова — обычная строка-команда слоя в углу, не ярче `dim`.

### 3.2. Экран START

После boot программа не идёт в меню. Она ставит доску того, что игрок будет играть (раздел 3.3), и показывает над ней экран START:

- поле и кости видны и затемнены так же, как под панелью паузы над партией (`PanelScreen` поверх доски, `alone: false`);
- фигуры на кубе нет;
- посередине одна большая кнопка `START` — слово в языке игрока (всё нажимаемое переводится, решение 6 октября; слово `START` в `src/shell/text.ts` и `src/ui/lang/words.ts`). Вид — **как у других кнопок меню**: та же залитая строка-команда с красной меткой седьмого, теми же цветами палитры (`ink`, `bg`), только крупнее. Нового цвета в теме нет: слово владельца 8 октября — «держи визуал в рамках, не давай ему расползаться». Высота кнопки не меньше двух пальцев, ширина — половина поля;
- ничего больше: ни названия, ни номера уровня, ни строк.

Нажатие (палец, мышь, Enter, пробел): затемнение уходит, фигура появляется на кубе игрока тем же приходом, каким она встаёт на доску сейчас (`riseIn` в `begin`, `view.reset(true)` для фигуры; кости уже стоят), управление включено. Знак свайпа этапа 1 появляется в тот же миг.

Экран START показывается при каждом запуске программы, не только первом.

### 3.3. Куда ведёт START

| Состояние | Что стоит под экраном START |
|---|---|
| Первый уровень не пройден (`settings.levels.passed['F1']` нет) | этап 1 первого уровня |
| Первый уровень пройден | первый непройденный уровень списка (`nextLevel()` в `src/app/game.ts`); все пройдены — первый |
| В хранилище лежит сохранённая партия (`keptRun`) | как сейчас: партия продолжается с её паузы; экрана START нет |
| `?levels`, `?tutorial`, `?tasks`, `?lab` | как сейчас, без экрана START |

Меню (`showMenu`) открывается только из паузы командой `MENU`, как сейчас. Из меню файл `LEVELS` открывает список, как сейчас.

## 4. Лента

### 4.1. Что такое лента

Этапы первого уровня и уровни списка идут одной лентой. Конец уровня не открывает окно: кости уходят, поле перерисовывается (раздел 8), игрок стоит на кубе следующей доски, управление включено. Так между этапами 1→2→3→4, после этапа 4 → `P01`, и дальше `P01`→`P02`→…, пока игрок сам не выйдет в паузу.

Список уровней владелец пересоберёт позже; лента идёт по порядку `LEVELS` как он есть.

### 4.2. Итог уровня в ленте

Уровень списка пройден — над доской во время перерисовки стоит **строка итога**: звёзды (`★★☆` знаками программы, как в списке уровней) и число ходов, одной строкой, в месте и размере показаний уровня (`hud.ts`, строка `moves`), без рамки, без команд. Стоит, пока идёт перерисовка, и гаснет с первым ходом новой доски. Лучший результат и прочее — в списке, как сейчас.

Этапы первого уровня строки итога не имеют: звёзд у них нет (раздел 6.6).

Уровень **проигран** (тупик, предел ходов) — как сейчас: пауза `FAIL_HOLD_MS`, окно `FAILED` с причиной и `UNDO`. Это окно нужно: оно единственное, где игрок видит причину.

### 4.3. Пауза

Как сейчас (`pausePanel`): `RESUME`, `RESTART`, `LEVELS`, `SYSTEM`, `MENU`. На этапах первого уровня `RESTART` начинает заново текущий этап. Список уровней не меняется: первого уровня в нём нет. Сыграть его снова — адресом `?first` (как `?tutorial` открывает упражнение); он же нужен владельцу для проверки.

## 5. Правила: одно касание

Всё, что ниже, — в `src/rules`, с тестом; остальные правила уровня не меняются. Запись на страницу правил — раздел 10.

### 5.1. Раскладка с уходящей костью и игроком на полу

`LevelLayout` (`src/rules/types.ts`) получает два необязательных поля:

```ts
export interface LevelLayout {
  dice: readonly PuzzleDie[];
  start: { x: number; z: number };
  /** Dice of `dice`, by index, that are already leaving when the board is laid: each goes in this many moves. */
  leaving?: readonly { die: number; moves: number }[];
  /** The player starts on the floor of `start`, which then holds no die. Left out, they start on the die at `start`. */
  onFloor?: boolean;
}
```

`placeLevelLayout` (`src/rules/spawn.ts`) после `addCube` для каждой записи `leaving` делает кость уходящей: `state = 'sinking'`, `reactionId` — новая реакция `{ id, value: top, chain: 1, total: 1 }` в `state.reactions`, `t = sinkingTicks − moves · actionTicks` (так кость уйдёт ровно через `moves` ходов; с `moves: 1` она стоит наполовину опущенной — вторая стадия ухода). `createRun` при `onFloor` ставит `player.level = 'ground'`.

`checkLayout` (`src/rules/level.ts`): при `onFloor` на `start` кости нет и `start` — клетка поля; без `onFloor` — как сейчас; `leaving` ссылается на существующие кости, `moves` от 1 до `sinkMoves`.

Что уже работает и только проверяется тестом (`src/rules/level.test.ts` или новый `src/rules/firstLevel.test.ts`):

- с пола на такую кость поднимаются (`mount`, высота ≤ `mountHeight`); с неё шагают на стоящую (`hop`) и сходят обратно на пол (`descend`, пол открыт);
- шаги мир не двигают: после `mount` и `hop` у кости тот же `t`;
- первый ход убирает её (`removeCube`), реакция вычищается (`pruneReactions`);
- она не стоит (`standing`), поэтому в цели «очистить» уже посчитана: `cleared = norm − standing` даёт `1/4` до первого хода; `norm` считает её (`checkLayout` требует `layout.dice.length === norm`);
- на неё можно накатить свою кость (`roll` по уходящей: она исчезает сразу);
- метки множителя (`HudLabel`, `labels` в `hudView`) над группой из одной кости нет: условие на `chain > 1` или `total > 1` — исполнитель смотрит, что там сейчас, и закрывает дыру тестом;
- решатель (`solveLevel`, `solveFrom`) принимает такую доску: он ходит настоящими правилами от `createRun`, так что это проверка, а не правка; `tryWay` проигрывает путь этапа 2 с шагами `mount` и `hop` — если запись пути (`x,z,D`) шагов не знает, путь этапа записывается с первого переката, а шаги до него проверяет тест отдельно.

### 5.2. Что не меняется

Ход и шаг, комбо и цепочка, рабочие грани, пол, тупики, отмена — как на странице правил. Endless, сеанс дня, упражнение, задачи — не трогаются; `RULES_VERSION` прежний.

## 6. Первый уровень: четыре этапа

### 6.1. Как этапы устроены в коде

Первый уровень — четыре обычных `LevelSpec` в новом файле `src/levels/first.ts` (`FIRST_LEVEL: readonly LevelSpec[]`, ids `F1a`…`F1d`), и запись о нём как об одном уровне для списка и хранилища (`id: 'F1'`). У каждого этапа: `arrival: 'none'`, `goal: { kind: 'clear' }`, `moves: 0`, `undos: 3`, `sinkMoves: 2`, `liftMoves` как у `P01`, `faces` этапа, `floor` этапа, `layout`, `par`, `exact: true`, `solution`. Полей `lesson`, `arrow`, `guide`, `story` у этапов нет.

Оболочка (`src/app/game.ts`) ведёт этап как уровень (`startLevel` с указанием спеки), а конец этапа (`endReason === 'passed'`) не открывает `levelResultPanel`, а запускает переход ленты (раздел 8) к следующему этапу; после `F1d` — к `LEVELS[0]`. Пройден `F1d` — `settings.levels.passed['F1'] = true`, `levelStat('F1')` получает попытку без `bestMoves`.

Система координат: `x` на восток (вправо), `z` на юг (к камере). Камера стоит с юго-востока (`DEFAULT_CAMERA` yaw 30, pitch 38): игрок видит верх, **южную** грань целиком и **восточную** частично. Перекат на север (от себя) поднимает южную грань, перекат на запад (влево) — восточную (`roll` в `src/rules/orientation.ts`).

Картинки ниже: `#` клетка, `.` вырезана (`holes`), буквы — кости; `z` растёт вниз.

### 6.2. Этап 1 — двойка на полосе (`F1a`)

```
size 6, faces [2], floor false
z=2:  A # # # # B      x = 0..5; все остальные клетки квадрата 6×6 вырезаны (30 отверстий)
```

| Кость | Клетка | top | north | Остальное |
|---|---|---|---|---|
| A, игрок | (0,2) | 2 | 3 | south 4, east 1, west 6, bottom 5 |
| B, цель | (5,2) | 2 | 3 | |

`start: (0,2)`. Путь `0,2,E 1,2,E 2,2,E 3,2,E`; `par: 4`. Верхняя грань A по клеткам: 2 → 6 → 5 → 1 → 2. На (4,2) двойка наверху рядом с B: комбо из двух, обе уходят.

Что держит этап:

- игрок в торце: доступен один перекат; свайп в другие стороны ход не тратит (край);
- полоса — дерево: грань наверху зависит только от клетки, куда бы игрок ни катался; у цели всегда двойка;
- проиграть нельзя: две кости, комбо просит две, тупика по счёту нет; пол закрыт.

Знак свайпа (раздел 7.1) стоит с первого кадра и показывает восток. Плашка (7.2) над B: один кубик из двух горит.

### 6.3. Этап 2 — тройка за поворотом, с лесенкой (`F1b`)

```
size 5, faces [3], floor true
z=0:  . . D C .
z=1:  . . . # .
z=2:  S A # # .
z=3:  P . . . .
```

| Кость | Клетка | top | north | Состояние |
|---|---|---|---|---|
| S, лесенка | (0,2) | 6 | 2 | уходит, `leaving: [{ die: 0, moves: 1 }]`: стоит наполовину опущенной |
| A, игрок катит | (1,2) | 1 | 4 | south **3**, east 2, west 5, bottom 6 |
| C | (3,0) | 3 | 1 | |
| D | (2,0) | 3 | 2 | |

`start: (0,3)`, `onFloor: true`: фигура стоит на полу в кармане P. Клетки: (2,0), (3,0), (3,1), (0,2), (1,2), (2,2), (3,2), (0,3); остальные 17 вырезаны.

Путь: шаг N на лесенку (0,2), шаг E на A, перекат `1,2,E`, `2,2,E`, `3,2,N`; `par: 3`. Верхняя грань A: 1 → 5 → 6 → **3**. На (3,1) тройка наверху рядом с C и D: комбо из трёх.

Что держит этап:

- из кармана единственный сосед — лесенка: игроку нечего делать, кроме как подняться; на полу толкать нечего (`floorStuck` не срабатывает: `canMove` видит подъём);
- лесенка уходит с первым перекатом игрока: он видит, что мир двигается его ходом и что собранное уходит вниз;
- перекаты вдоль полосы не трогают северную и южную грани: тройка ждёт на южной, сколько бы игрок ни катался; поле — дерево, грань на (3,1) всегда 3;
- лишние движения: перекат W по лесенке (она исчезает сразу, A встаёт на (0,2)), перекат S в карман и обратно; худшее положение — пять ходов до комбо; проиграть нельзя: три кости на комбо из трёх, с пола в карман после ухода лесенки не попасть (со стоящей кости на пол не сходят).

Знак свайпа не стоит со старта: приходит по простою (7.3) и показывает ближайший ход решателя: сначала подъём (N), затем шаг (E), затем перекаты. Плашка над C и D: два кубика из трёх горят.

Лесенка выглядит как любая уходящая кость (матовая, через сетку точек, наполовину внизу). Никаких слов и знаков у неё нет: по слову владельца это декорация, которая объяснится много позже.

| A, игрок | (1,1) | 1 | 2 | east **3**, south 5, west 4, bottom 6 |
| C | (0,0) | 3 | 1 | |
| D | (1,0) | 3 | 2 | |

`start: (1,1)`. Клетки: (0,0), (1,0), (0,1), (1,1), (2,1); вырезаны (2,0) и весь ряд z=2 (size 3). Путь `1,1,W`; `par: 1`. Перекат на запад поднимает восточную тройку на (0,1), рядом с C.

Отличается от этапа 2: не поворот после полосы, а один перекат влево, и грань, которую надо поднять, — восточная, не южная. Лишнее: перекат E на (2,1) и назад; шаг N на D и перекат D с места (пару можно разобрать) — худшее положение пять ходов до комбо, тупика нет (три кости, комбо из трёх; пол закрыт). Знак по простою показывает ход решателя из текущего положения, что бы игрок ни наделал.

### 6.6. Что общее у этапов

- Нет предела ходов, звёзд, строки итога, окна перед уровнем, окна после.
- Отмена: три на этап, командой из паузы, как на любом уровне. Тупика на этапах нет, окно `FAILED` не открывается.
- Нерабочие грани перечёркнуты, как на любом уровне (решено раньше, не меняется).
- Переход к следующему этапу — ровно тогда, когда последнее комбо этапа ушло: финал уровня (`finaleOver`) играется как сейчас, за ним не окно, а перерисовка (раздел 8).
- Все четыре доски доказаны решателем: `par` и `solution` проигрываются тестом списка, как у `P01`–`P30` (`src/levels/levels.test.ts`); сверх того тест первого уровня проверяет на каждом этапе, что из каждого достижимого положения доска решается (`solveFrom` по обходу состояний) и что число ходов до решения из худшего положения не больше 5. Числа этой страницы считаны тем же перекатом (`roll`) 8 октября.

## 7. Знаки

Все знаки — в слое интерфейса; строки для [VI_Interface_Layer.md](../../art/VI_Interface_Layer.md) — раздел 10. Вид — за владельцем; ниже место, поведение и то, из чего знак собран.

### 7.1. Знак свайпа

Что: рядом с полем, на стороне, куда нужен перекат, **точка** цвета фигуры (`figure` темы) проезжает короткий след в этом направлении и гаснет, снова и снова; на клавиатуре вместо точки — знак стрелочной клавиши шрифта программы (`←↑→↓`, как стрелки файлов меню). Какая из двух форм — по `settings.controlMode` и по тому, чем игрок управлял последним (`gesture` — точка; клавиши — стрелка).

Где: вне поля, у его края со стороны направления, на высоте фигуры; не на клетках. На телефоне в положении «следом за игроком» — у края экрана с той же стороны.

Когда:

- этап 1 — с первого кадра после START, направление E; гаснет с первым ходом;
- любой этап и любой уровень — по простою (7.3), направление — ближайший ход решателя отсюда (`solveFrom`); для шага (подъём, шаг на кость) — то же направление;
- гаснет с ходом или шагом; не показывается, пока открыта панель.

Опора: Monument Valley и Threes показывают первый жест скользящим знаком, который гаснет при касании; Lind (2016) — подсказка по простою оценивается лучше, чем стрелки за руку и чем отсутствие помощи.

Слов у знака нет ни на одном языке: знак без слова работает на семи языках сразу.

### 7.2. Плашка неполного комбо из кубиков

Сейчас: плашка с гранью и «2/3» (`drawCounter` в `src/shell/hud.ts`, `HudCounter`). Новое: вместо текста `have/need` — `need` маленьких кубиков в ряд, каждый с гранью комбо (та же `plateFace`), первые `have` — полным тоном, остальные — `faint`. На первом уровне — над каждой кучкой рабочей грани, которая меньше комбо, со старта, **включая одну кость** (`shortGroups` считает от двух; для первого уровня нужна и одна стоящая кость рабочей грани, кроме той, на которой стоит игрок: отдельный отбор в `game.ts` по `spec.id` первого уровня, `shortGroups` не трогать). На уровнях списка меняется только вид плашки: где она стоит (`CHAPTERS_COUNTED`, кучка последнего хода) — как сейчас.

На этапах 3 и 4 плашка над целью **мигает** (чередует полный тон и `faint` раз в полсекунды) первые секунды простоя, до прихода знака свайпа (7.3).

### 7.3. Простой

Счётчик простоя — время с последнего хода или шага, пока нет панели и идёт партия. Пороги (предложение исполнителя, числа — первая прикидка, владелец их не называл):

| Что | Этап 1 | Этапы 2–4 |
|---|---|---|
| Знак свайпа со старта | да | нет |
| Плашка цели мигает | — | с 4 с |
| Знак свайпа по простою | с 6 с после ухода знака | с 8 с |
| Пустые ходы (сделано − продвижение по решателю ≥ 3) | — | знак сразу |

Знак по простою приходит снова через те же секунды после нового простоя. Если доска отсюда не очищается (`solveFrom` пути не нашёл), знака нет. На этапах такого положения нет (6.6). На уровнях списка знака по простою пока нет: владелец о подсказках на них не говорил (раздел 13).

### 7.4. Что убирается

- Стрелка прочитанного свайпа (`steerGuide`, `steer`, `STEER_LINGER_MS`, `GuideArrow.stand`): везде — уровни, Endless, сеанс дня, упражнение. Поведение жеста не меняется: шаг по отпусканию, возврат пальца к началу отменяет (`GestureTracker`, `onRelease`); меняется только то, что ничего не рисуется.
- Стрелка первого хода (`levelGuide`, `LevelSpec.arrow`, `BoardGuide.arrows` на уровнях): убрана; поле `arrow` в `LevelSpec` удаляется, в `levels.ts` его нет.
- `BoardGuide.arrows` остаётся в упражнении (`?tutorial`), которое из меню не открывается; если упражнение без стрелок ломается — стрелки остаются только там, и это записывается в слой как «только упражнение».

## 8. Перерисовка поля

Что должно произойти между досками ленты, словами владельца: «стильно и анимированно… в духе нашего визуала… загадочное, ритуальное и эффектное действие». Вид ведёт он; ниже — порядок и из чего это собрано, чтобы исполнитель собрал первую версию, которую владелец правит на глаз.

Порядок (всё в канвасе и в сцене, без DOM):

1. **Уход.** Последнее комбо ушло, финал уровня как сейчас: кости под пол, ответ доски по линиям (`leaveBoard`, `answer`). Фигура остаётся стоять на полу там, где была.
2. **Погасание.** Линии сетки и тяжёлая линия края старой формы гаснут не разом, а «строчками» — по рядам клеток, сверху вниз, как кадр трубки, который перестают рисовать: это та же сетка точек, через которую рисуются кости, только для линий (`gridTexture`, `frameTexture` в `src/render/textures.ts`; покадровое обновление текстуры по маске рядов). Длительность ~0,5 с.
3. **Проявление.** Новая форма проявляется теми же строчками: сначала тяжёлая линия края, по рядам, затем сетка внутри. Одновременно на клетках новой доски **собираются кости** — тем же приходом через сетку точек, каким кость сейчас приходит в сеансе (`rising` → `idle`, `risingTicks`): они набирают точки и свет. Лесенка этапа 2 проявляется до половины и там останавливается. Длительность ~0,8 с.
4. **Фигура.** Переходит на свою новую кость: не телепорт, а короткий проход тем же шагом, каким она ходит по доске (`player.ts`), если новая клетка в двух-трёх клетках; дальше — исчезает и проявляется через ту же сетку точек. Этап 2: фигура проявляется на полу в кармане.
5. **Управление включается** на последнем кадре проявления; строка итога (4.2), если была, гаснет с первым ходом.

Камера: в положении «следом за игроком» вид мягко переезжает на новую доску во время шага 3. На широком экране доска и так в середине.

Звук: три события для `src/audio` — уход (есть), проявление (нужно: тихий тон прихода костей, как у прихода в сеансе), шаг фигуры (есть). Новых звуков не сочинять: взять те, что есть у прихода кости и ответа доски; владелец слушает и говорит.

Уменьшенное движение (`reducedMotion`): без строчек, доска меняется за один кадр с проявлением костей.

Техника: `useView(size, holes)` держит по виду на форму; переход рисует два вида один за другим или один вид с переключением формы — исполнитель выбирает по коду `BoardView` и записывает в плане. Переход — состояние оболочки (`handoff` или новое поле `ribbon` в `game.ts`) с временем начала; пока он идёт, ввод выключен (`inputEnabled`), партия следующего этапа уже создана (`createRun`) и не тикает.

## 9. Хранение и платформа

- `settings.levels.passed['F1']`, `settings.levels.stats['F1']` — как у любого уровня, этапы отдельно не хранятся. Выход из середины первого уровня (закрытие вкладки) — при следующем запуске снова этап 1: сохранённой партии (`keptRun`) первый уровень не оставляет.
- Уровни списка в ленте сохраняются как сейчас (`keptRun` между запусками, `levelStat`).
- Телеметрия платформы (`track`, `tell` в `game.ts`): `progression_started`/`completed` по этапам с `id` этапа, как у уровней; новых событий не заводить: собирать их владелец пока не может.
- Язык: один новый ключ `start` в семи языках (`src/ui/i18n.ts`, `src/ui/lang/*.ts`, тест `src/ui/lang/words.test.ts` или где лежат проверки полноты).

## 11. Проверка

- `npm test`, `npm run typecheck`, `npm run build`.
- Тесты: правила (5.1), четыре доски (6.6), знак и простой (чистые функции времени и состояния в `src/app`, тест как у `hints`), плашка (`hud` тест с кубиками), i18n полнота.
- Руками через preview `vi-dev` (порт 5183) с чистым хранилищем (`localStorage.removeItem('vi.settings.v3')`): boot → скип → START → четыре этапа → `P01`, ни одного окна по пути; пауза → `MENU` работает; второй запуск: START ведёт на `P01`; телефонная ширина 360 и экран 1080: кнопка START не меньше двух пальцев, знак свайпа виден у края, строка итога читается. Снимки обоих экранов — в отчёт.
- Живой просмотр: владелец сажает за игру человека, который её не видел, и смотрит молча. Это единственное мерило понятности; боты её не меряют.

- Слова лаборанта, строка у доски, окна истории, текст о связи точек и числа костей.
- Переделка списка уровней, звёзды и предел на первом уровне, ворота.

- Вид кнопок, цвета, звук проявления — первая версия исполнителя, правит владелец.

## 13. Открыто у владельца

1. Вид скипа — до его слова первая версия по разделу 3. Цвет START решён: как у других кнопок.
2. Числа простоя (7.3) — первая прикидка.
3. Вид перерисовки (8) — первая версия по порядку шагов, правится на глаз.
4. Имя первого уровня в списке — пока `F1` без имени, как у `P`-уровней.
5. Нужен ли экран START вернувшемуся игроку с сохранённой партией — решено «как сейчас: партия продолжается», можно пересмотреть.
6. Знак по простою на уровнях списка: сейчас его там нет; новый игрок после этапа 4 попадает на `P01` без подсказок.

## 14. Готово, когда

- Чистый запуск: boot со скипом, START, четыре этапа без окон и слов, лента в `P01`; меню — только из паузы.
- Второй запуск: START ведёт на первый непройденный уровень.
- Правила: раскладка с уходящей костью и игроком на полу, с тестами; больше в `src/rules` ничего не изменено (`git diff --stat src/rules`).
- Четыре доски доказаны: `par`, `solution`, решение из любого положения, худшее ≤ 5 ходов.
- Стрелок на поле нет ни в одном режиме; знак свайпа и плашка из кубиков на месте.
- Перерисовка поля играется между этапами и между уровнями; строка итога на уровнях списка.
- Все страницы раздела 10 правлены; `npm test`, `typecheck`, `build` зелёные; снимки телефона и экрана в отчёте.
