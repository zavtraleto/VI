## Коротко

Шесть новых досок актов I и II генератор места не дал: ноль досок на пять с лишним тысяч зёрен. Доски нашли временные скрипты: три — перебором раскладок, три — кладкой назад от конца. Спека делает из этих скриптов команду лаборатории `lay`.

1. Место получает **замысел** (`plot`): какие кости стоят, какие приходят, за сколько перекатов и как, в каком порядке события, какой фигурой всё кончается и чему доска учит.
2. Доска кладётся **назад от конца**: каждая кость ставится на клетку своего события рабочей гранью вверх и откатывается оттуда. Перебор вперёд остаётся запасным способом.
3. Проверка вперёд идёт **воронкой**: раскладка даром, путь за миллисекунды, урок за доли секунды; боты, обход и доказательства — только сорока лучшим.
4. Уроки места — **мерила**, а не слова в `brief`.
5. Выдача — **пять финалистов** разной формы файлами в `boards/`, по одной и вслепую. Владелец играет и ставит отметки, следующий круг кладёт ближе к «огням».
6. На странице лаборатории — **кнопка «от замысла»**: первая доска за секунды, остальные ищутся, пока он играет. Команда `lay` остаётся для полного перебора и отчёта.
7. В работу входит **бот, который читает кость**: нынешние персоны не различают доски со спрятанной гранью.

Правила уровня не меняются; в `src/rules` добавляется только новая персона в `levelBot.ts`. Нынешние `gen`, `order`, `fit` и судья мест остаются как есть.

## 2. Что решено

| № | Решение |
|---|---|
| 1 | Вход генератора — замысел `Plot`, новое поле `plot` у `Recipe`. Числовые границы рецепта остаются и работают как фильтры воронки. |
| 2 | `Scene` и `layFromRoute` не трогаются: места пробы и дороги кладутся как раньше. Замысел из `scenes` получается механически (`plotOf`), так что старое место можно положить и новой командой. |
| 3 | Основной способ — кладка назад полным перебором откатов, а не случайными зёрнами. Выборка по зерну — только когда раскладок больше предела. |
| 4 | Перебор вперёд — запасной: когда бриф описывает начало, а не конец; когда нужен ответ «такой доски нет»; когда кладка назад дала ноль. |
| 5 | Порядок событий задан, порядок тихих ходов — нет. Доска сверяется с замыслом по событиям кратчайшего пути, а не по записанной последовательности ходов. |
| 6 | Проверка — четыре ступени по цене. Боты, обход, доказательство необходимости приёма и `near` считаются только у финалистов. |
| 7 | Уроки — мерила в `src/levels/measures.ts`: «держит ровно N ходов», «приманка ведёт в тупик на глубине N», «грань на виду и не заслонена». |
| 8 | Команда — `node scripts/level.mjs lay place=…`; доли по процессам, журнал по ходу и отчёт воронки — в самой команде. Рядом — команда `passport`. |
| 9 | Финалистов пять на круг (слово владельца). Они пишутся в `boards/` со статусом `idea` и заметкой со слова «место»: страница открывает такие вслепую, по одной. Паспорт лежит отдельно и владельцу до игры не показывается. |
| 10 | Отметки владельца управляют порядком финалистов следующего круга (ближе к «огням», дальше от «мимо», без повторов формы). Слова владельца правят сам замысел — это делает агент. Модели из оценок нет. |
| 11 | Полы нынешних персон на досках со спрятанной гранью из ворот становятся строкой паспорта. Строится пятая персона, которая читает кость (раздел 10); её пол становится воротами после сверки с партиями владельца. |
| 12 | Генерация от замысла есть и на странице: кнопка, ответ за секунды (раздел 8.1). Замысел пишет агент по брифу; панели замысла нет. |
| 13 | Ход, после которого доска проходится только долгим обходом без объявленного тупика, — недостаток доски: такие доски идут в конец очереди и выдаются с пометкой, а длина обхода пишется в паспорт (раздел 6.1). |
| 14 | Два «мимо» подряд на одном месте останавливают выдачу: агент спрашивает владельца о замысле. |

## 3. Замысел: что добавляется к рецепту

### 3.1. Тип

Новый файл `src/levels/plot.ts`, новое поле `plot?: Plot` в `Recipe`.

```ts
/** Где у кости рабочая грань, как её видит игрок: камера стоит с юго-юго-востока. */
export type Side = 'top' | 'south' | 'east' | 'north' | 'west' | 'under';

/** Как кость приходит на клетку своего события. Назад это её откат. */
export interface Coming {
  by: 'roll' | 'push';
  /** Перекатов (или клеток толчка), от и до. */
  rolls: readonly [number, number];
  /** По прямой, с поворотом или как выйдет. Только для переката. */
  line?: 'straight' | 'turn' | 'any';
  /** Перекатов, которые уводят кость от клетки события: «увезти и вернуть». Ноль, если не сказано. */
  away?: number;
  /** Путь может идти по клетке кости, которая уже уходит (`glass`). Нет, если не сказано. */
  overLeaving?: boolean;
  /** Где рабочая грань на старте: любое из названных. Не сказано — где выйдет. */
  starts?: readonly Side[];
  /** Эта грань на старте не заслонена соседом (раздел 6.3). */
  open?: boolean;
}

export interface PlotDie {
  /** Один знак: им кость стоит на картинке фигуры. `o` — кость, на которой стоит игрок. */
  name: string;
  /** Грань, которой кость уходит. */
  face: number;
  /** Номер события, с которым она уходит. */
  event: number;
  /** Нет — кость стоит с начала на клетке события гранью вверх. */
  comes?: Coming;
}

export interface PlotEvent {
  kind: 'combo' | 'link' | 'ones';
  /** Кость, чей последний перекат делает событие. */
  by: string;
  /** У звена: сколько ходов оставалось уходящим (0 — последний возможный). */
  spare?: number;
}

export type Lesson =
  | { kind: 'keeps'; after: number; moves: readonly [number, number]; slack?: number }
  | { kind: 'bait'; at: number; move: 'event' | 'greedy'; fate: 'dead' | 'longer'; depth?: readonly [number, number]; over?: number }
  | { kind: 'safeFirst' };

export interface Plot {
  dice: readonly PlotDie[];
  /** События по порядку. Порядок ходов между ними не задаётся. */
  events: readonly PlotEvent[];
  /** Фигура конца: картинка из имён костей на клетках их событий, ряд за рядом с севера; `.` — что угодно. */
  figure?: readonly string[];
  /** Фигура стоит как нарисована (`true`) или кладётся со всеми сдвигами, поворотами и отражениями. */
  pinned?: boolean;
  lessons?: readonly Lesson[];
}
```

Каждая кость доски входит в какое-то событие: уровень — очистка, лишних костей нет. Фигура — клетки событий, а не снимок одного мига: к приходу дальнего звена первые кости уже ушли вниз.

### 3.2. Как слова брифа ложатся на поля

| Слова брифа | Поле |
|---|---|
| «пара стоит» | две кости без `comes` в одном событии |
| «приходит за два переката по прямой» (грань была внизу) | `rolls: [2, 2], line: 'straight'`; тогда `starts` сам выходит `under` |
| «один перекат, грань лежала на видимом боку» | `rolls: [1, 1], starts: ['south', 'east'], open: true` |
| «увезти и вернуть» | `away: 1` |
| «без проката по уходящей» | `overLeaving` не ставится; на третьей ступени сверяется с `avoid: ['glass']` |
| «пять троек крестом» | `figure: ['.a.', 'bcd', '.e.']` |
| «звено на последнем возможном ходу» | `spare: 0` у события |
| «ранний ход спасает, поздний нет» | урок `keeps` |
| «комбо, которое просится, бросает кости» | урок `bait` |

Три инварианта кости из журнала акта I («два переката в линию — грань уходит вниз», «один перекат — грань на боку», «туда и обратно возвращает») не становятся отдельными шаблонами: это следствия `rolls`, `line` и `away`. Перебор кладёт все откаты, которые держат эти поля, и оставляет те, где грань легла туда, куда велит `starts`.

### 3.3. Пример: открытие акта II

```ts
plot: {
  dice: [
    { name: 'a', face: 2, event: 0 },
    { name: 'o', face: 2, event: 0, comes: { by: 'roll', rolls: [1, 1] } },
    { name: 'n', face: 2, event: 1, comes: { by: 'roll', rolls: [1, 1] } },
    { name: 'f', face: 2, event: 2, comes: { by: 'roll', rolls: [2, 2], line: 'straight', overLeaving: true } },
  ],
  events: [{ kind: 'combo', by: 'o' }, { kind: 'link', by: 'n' }, { kind: 'link', by: 'f', spare: 0 }],
  lessons: [{ kind: 'keeps', after: 0, moves: [1, 1], slack: 2 }, { kind: 'safeFirst' }],
}
```

Это то, что `k23.mjs` держал в коде циклов и в комментарии. `line: 'straight'` здесь не украшение: путь с поворотом оставляет грань на боку, и дальняя кость приходит за один перекат — урок обходится.

### 3.4. Что остаётся у рецепта и что уходит

Остаётся и работает фильтром: `size`, `holes`, `faces`, `par`, `standing`, `needs`, `avoid`, `shows`, `kinds`, `route`, `quiet`, `counted`, `last`, `links`, `silence`, `tail`, `ends`, `firsts`, `room`, `blind`, `under`, `underShare`, `islands`, `compact`, `trap`, `safeFirst`, `brief`. Число костей (`dice`) у места с замыслом берётся из замысла, и тест сверяет одно с другим.

Не спрашивается у места с замыслом, если оно само не назвало: `random`, `traps`, `worst`, `lossless`, `personas`, `hasty`, `casual`, `gap`. Они считаются у финалистов и идут в паспорт. Причина в журналах: `lossless` и `worst` на открытой доске не держит ни одна раскладка, полы персон на спрятанной грани — ни одна доска акта.

`front`, `ride`, `seven` остаются мерилами старых мест; у новых их работу делают `starts` и `open`.

## 4. Кладка назад и перебор вперёд

### 4.1. Назад — основной способ

Чистый модуль `src/levels/layBack.ts`: генератор раскладок по замыслу и форме поля.

1. **Клетки событий.** С фигурой — все её положения на поле (сдвиги; повороты и отражения, если не `pinned`). Без фигуры — все расстановки, где кости комбо стоят бок о бок, а кость звена касается своей цепочки.
2. **Откаты.** Кость с `comes` ставится на клетку события рабочей гранью вверх и катится назад: для каждого числа перекатов из `rolls` — все пути, которые держат `line` и `away`. Толчок — сдвиг по линии той же гранью вверх, за костью остаётся свободная клетка для игрока (как `slideAway` в `src/levels/route.ts`).
3. **Отсев на месте** (ступень 0, раздел 5).
4. **Старт игрока** — кость `o`.

Откат не проверяет, свободны ли клетки по пути: это зависит от порядка ходов, а он не задан. Проверяются только край поля и вырезы; остальное решает проверка вперёд. Так делали оба прототипа, и так кладка не теряет доски, где кость едет через клетку, с которой другая уже ушла.

Ядро отката — десять строк из `k23.mjs`, переносится как есть:

```js
const back = (cell, dirs) => {            // dirs — перекаты, которыми кость придёт
  let o = UP, c = cell;                   // UP — рабочая грань вверх
  for (const dir of [...dirs].reverse()) {
    o = roll(o, OPP[dir]);
    c = at(c.x - D[dir][0], c.z - D[dir][1]);
    if (!c) return null;                  // край или вырез
  }
  return { x: c.x, z: c.z, top: o.top, north: o.north };
};
```

Чего кладка назад не знает и что поэтому всегда сверяется вперёд: два хода, за которые уходит комбо, и ход, на который звено придерживает уходящих; может ли игрок дойти до кости; не открыло ли раннее событие путь короче.

**Сколько раскладок.** Перед кладкой команда считает размер пространства (положения фигуры × откаты каждой кости). До предела (`limit`, 200 000 — три минуты на шести процессах по замеру `K25`) оно перебирается целиком. Больше — равномерная выборка по зерну, и отчёт говорит об этом первой строкой. Ответ «такой доски нет» честен только после полного перебора.

### 4.2. Вперёд — запасной способ

Модуль `src/levels/layForward.ts`. Замысел тот же, но у костей нет откатов: перебираются клетки и положения рабочей грани.

- На доске одной грани у кости важны шесть положений (где эта грань), а не двадцать четыре. Это взято из `k21.mjs`.
- Решатель ограничен верхом `par` и малым пределом досок (15 000): непроходимые раскладки — самые дорогие. Раскладка, на которой решатель сдался, в отчёте стоит отдельной строкой, а не пропадает.
- Годится для полей до 4×3 и до пяти костей; на большем команда отказывает и называет размер пространства.

### 4.3. Когда какой

| Положение | Способ |
|---|---|
| У каждой кости сказано, как она приходит | назад |
| Бриф описывает вид начала («две пары и зазор между ними») и откатов не называет | вперёд |
| Нужен ответ «бывает ли такая доска на этом поле» | вперёд, целиком |
| Кладка назад дала ноль, и отчёт говорит «есть путь короче» у большинства | сначала править замысел (`line`, `rolls`, число костей); вперёд — если поле мало |
| Поле больше 4×3 или костей больше пяти | только назад |

Ключ `mode=auto` выбирает по первой и второй строке.

## 5. Воронка проверки

Чистая функция `judgePlot(recipe, board, upto)` в `src/levels/plotJudge.ts`. Ступени идут от дешёвого к дорогому; первая несдержанная проверка — причина отказа; причины считаются по ступеням и идут в отчёт. Функция отдельна от команды, чтобы её потом могли звать `repair` и `improve`.

| Ступень | Что спрашивается | Цена на доску | Кому |
|---|---|---|---|
| 0. Раскладка | клетки костей различны; готовой группы нет; единица сверху только там, где её положил замысел; `starts` и `open`; `standing`, `blind`, `under`, `room`, `islands`, `compact`; такой доски ещё не было (хеш `normalSpec`) | микросекунды | всем |
| 1. Путь | решатель с границей ходов = длина задуманного пути и пределом 20 000 досок: доска проходится; минимум равен задуманному, не короче; события кратчайшего пути те же, в том же порядке и теми же костями; `kinds`, `route`, `ends`, `last`, `quiet`; приёмы пути против `avoid` и `shows` | 6–10 мс назад, ~30 мс вперёд (раздел 1) | прошедшим 0 |
| 2. Урок | первый ход безопасен; `firsts`; уроки замысла (`keeps`, `bait`); `trap` | до секунды: `moves` на одно–два положения с пределом 50 000 досок на ход | прошедшим 1 |
| 3. Финалист | персоны (30 партий на каждую), жадный бот, обход (150 досок), доказательство `needs` и `parts`, `near` | 10–30 с | не больше `final` досок (40) |

**Задуманный путь кратчайший.** Доска, где решатель нашёл путь короче, отсеивается: урок на ней обходится. Причина пишется с тем, чем короткий путь отличается («кость f пришла за один перекат»), — по этой строке правят замысел. Доска, где минимум равен задуманному, но события другие, отсеивается тоже. Сверка идёт по событиям, а не по ходам: кладка `K25` с жёстким порядком шести ходов дала 2 доски из 60 000, со сверкой по решателю — 199.

**Что делает напрашивающийся ход.** Напрашивающимся считается ход, который можно посчитать, двух видов: `event` — любой ход, после которого сразу что-то уходит (комбо или звено под рукой); `greedy` — ход, который выбирает жадный бот. Куда падает взгляд человека, команда не считает; это остаётся проходу глазами и словам владельца после игры (его ответ 4: этого достаточно).

**Первый ход безопасен** — `safeFirstOf`, как сейчас. Ловушку на первом ходу владелец назвал редким приёмом («очень редко так можно делать»), поэтому урок `safeFirst` стоит у замысла по умолчанию и снимается явно.

**Финалистам.** Из прошедших вторую ступень берутся до `final` досок: сначала по одной от каждой формы (раздел 7.3), потом по близости к «огням» (раздел 8). Только им считается дорогое. При сорока досках и 10–30 с на доску это 1–3 минуты на шести процессах. На странице третья ступень считается в фоне уже после выдачи доски (раздел 8.1).

**Если не прошла ни одна.** Отдаются ближайшие: доски, дошедшие дальше всех, с тем, чего каждая не держит, — как у `order` (слово владельца: «дать ближайшую и сказать, какого параметра она не держит»). Отчёт называет ступень, на которой погибло большинство, и главную причину.

## 6. Уроки как мерила

Новые функции в `src/levels/measures.ts`, каждая с тестом на доске актов I–II.

### 6.1. `keepsOf`: после события доску держит ровно N ходов

Положение после события `after` на кратчайшем пути. Каждый ход из него спрашивается у `movesOf`. Ход «держит», если доска после него проходится не длиннее минимума плюс `slack` (0, если не сказано). Мерило — число таких ходов; урок просит его в границах `moves`.

Рядом печатаются три числа, потому что «не держит» бывает разным: сколько ходов ведут в объявленный сразу тупик, сколько — в тупик, который игра объявит позже, сколько оставляют длинный обход. На `K23` это и вышло: держит один ход, но из восьми остальных сразу объявлен тупиком один, а семь уводят в обход на 7–11 ходов. Третье число — брак по слову владельца («просто возить кости довольно скучно»), но доска с ним не выбрасывается: она встаёт в конец очереди и выдаётся с пометкой «обход N» в паспорте, где N — самый длинный обход после одной ошибки. По отметкам таких досок станет видно, сколько ходов после ошибки ещё терпимо; тогда N получит границу в замысле (`detour`), и доски сверх неё будут отсеиваться.

### 6.2. `baitOf`: приманка ведёт в тупик на глубине N

Положение после `at` ходов пути. Приманка — ход вида `event` или `greedy` (раздел 5), которого нет в кратчайшем пути. `fate: 'dead'`: после неё доска не проходится, и глубина — сколько ходов ещё можно сделать, прежде чем игра объявит тупик (счёт как у `trapDepthOf` в `src/levels/orders.ts`; 0 — объявлен сразу). `fate: 'longer'`: проходится, но не короче минимума плюс `over`.

Отличие от нынешнего `trapOf`: тот смотрит только первые два хода и не говорит глубины; `trapDepthOf` считает глубину, но тоже только на старте и после первого хода. `baitOf` принимает любое положение пути.

### 6.3. `sightOf`: грань на виду и не заслонена

Камера стоит с юго-юго-востока (поворот около 30°, `spaceYaw`): южная грань кости смотрит на игрока почти прямо, восточная — под углом, верхняя видна всегда, северная, западная и нижняя не видны.

Для каждой кости: где её рабочая грань (`Side`) и закрыта ли она. Южную грань закрывает кость на клетке южнее, восточную — кость на клетке восточнее. Кость на диагонали (юго-восток) в первом приближении не закрывает ничего. То же для пустой клетки события («виден ли зазор»): её закрывает кость южнее.

Это первое приближение по раскладке, без отрисовки. План сверяет его со снимками 360×640 на досках `K21`, `K22`, `K28`, где исполнитель записал, что видно, и правит правило диагонали по снимкам.

Мерило отделяет то, что `turns` слило: грань на видимом боку и грань, спрятанную совсем. `turns` и `away` не меняются — они в `src/rules/levelScore.ts`.

## 7. Команда `lay`

### 7.1. Ключи

```
node scripts/level.mjs lay place=K31 [ключи]
```

| Ключ | По умолчанию | Что значит |
|---|---|---|
| `place=` | обязателен | код места с замыслом (`campaignRecipes.ts`, `recipes.ts`, `roadRecipes.ts`); место только со `scenes` кладётся через `plotOf` |
| `mode=` | `auto` | `back`, `forward` или `auto` (раздел 4.3) |
| `out=` | `boards/out/<место>/` | журнал, отчёт и паспорта |
| `workers=` | 6, не больше числа ядер минус два | процессов; делит так же, как `regress` и `ladder.mjs` |
| `limit=` | 200000 | раскладок, до которых перебор полный; больше — выборка |
| `seed=` | 1 | зерно выборки |
| `states=` | 20000 | предел досок решателя на первой ступени |
| `upto=` | `final` | остановиться после ступени: `laid`, `path`, `lesson`, `final` |
| `final=` | 40 | сколько досок получают третью ступень |
| `keep=` | 5 | сколько финалистов пишется в `boards/` |
| `round=` | следующий свободный | номер круга в именах файлов |
| `like=` | `on`, если оценок пять и больше | ранжировать по отметкам владельца (раздел 8); `off` — не смотреть на них |
| `resume` | — | продолжить по журналу: готовые доли не кладутся заново |
| `dry` | — | только посчитать размер пространства и выйти |
| `json` | — | ответ в JSON, как у остальных команд |

Код выхода: `0` — финалисты записаны; `1` — ни одна доска не прошла (ближайшие всё равно в отчёте); `3` — выдача остановлена двумя «мимо» подряд (раздел 8); `2` — место или замысел не читаются.

### 7.2. Доли, журнал, отчёт

**Доли.** Единица работы — положение фигуры (или расстановка клеток событий); процесс `i` из `n` берёт каждую `n`-ю. Одна доля — секунды, так что запись идёт часто.

**Журнал.** Каждый процесс пишет свой файл `out/lay-<i>.jsonl` и дописывает его после каждой единицы: строка счёта (положено, прошло ступень 0, 1, 2, причины отказа) и строка на каждую доску, прошедшую первую ступень (раскладка, путь, что посчитано). Остановленный прогон ничего не теряет; `resume` читает журналы и пропускает готовое.

**Ход работы.** В `stderr` раз в пять секунд одна строка: сколько положено из скольких, сколько прошло каждую ступень, раскладок в секунду, сколько осталось.

**Отчёт** `out/report.txt` (и то же в `stdout`); числа в образце условные:

```
lay K31, круг 2, назад, перебор полный: 36 288 раскладок за 58 с (6 процессов)
0 раскладка   36 288 → 9 410    готовая группа 14 902; грань не там 8 120; повтор 3 856
1 путь         9 410 → 112      есть путь короче 7 300 (кость f за один перекат 6 911); события иные 1 544; не проходится 454
2 урок           112 → 31       после комбо держат 2 хода и больше 64; первый ход проигрывает 17
3 финалист        31 → 5        форм 11; взято по одной от формы, дальше по близости к огням
ближайшие из не прошедших: —
находки: все 112 досок ступени 1 идут по уходящей кости (glass)
```

Строка «находки» — отрицательные результаты, которые перебор знает, а случайная кладка сказать не может: приём, без которого не обошлась ни одна доска ступени; ступень, на которой не осталось ничего. Команда печатает их сама по счёту приёмов (`uses`) у прошедших.

### 7.3. Выдача финалистов

**Форма.** Форма доски — занятые клетки и положение рабочей грани у каждой кости, с точностью до сдвига (не до поворота: камера одна). Из 256 годных досок `K17` форм было шестнадцать; пять поворотов одной доски владельцу ничего не скажут. Финалисты берутся по одному от формы, пока формы есть.

**Файлы.** `boards/<место>-<круг><буква>.txt`: `K31-1a` … `K31-1e`. В голове: `id`, `status: idea`, `note: место K31, круг 1`, `par`, `exact`, `way`. Заметка начинается со слова «место», поэтому страница открывает доску вслепую (лаборатория, раздел 7): цифры, лента и виды решателя спрятаны до первой записанной партии. В заметке нет ни урока, ни чисел.

Формат файла доски не меняется. Буквы идут в случайном по зерну порядке, а не по рангу: место в списке не должно подсказывать, какую доску генератор считает лучшей.

**Паспорт.** `out/passport-<круг>.txt` и `.json`, по строке на финалиста, ключ — хеш версии доски. В нём: костей, поле, `par`, путь, маршрут и его вид, `turns`, `away`, `quiet`, `chain`, `last`, `tail`, `firsts`; первые ходы (держат, длиннее, тупик); `sightOf` по костям; значения уроков с тремя числами из 6.1; персоны, читающая кость и жадный бот; обход (худшее, проигранных, сколько досок видел); самый длинный обход после одной ошибки; `uses` и доказанные `needs`; форма; расстояние до «огней». Паспорт лежит в `boards/out/`, которого нет в git, и владельцу до его игры не показывается.

**Команда `passport`.** `node scripts/level.mjs passport file=<доска> …` печатает ту же строку для любой доски: файла, уровня списка, куска дороги. Это закрывает строку журнала «паспорта одной командой нет» и переносит `passport.mjs` прототипа.

## 8. Круг с владельцем

1. **Замысел.** Агент пишет `plot` места по брифу кампании.
2. **Кладка.** кнопкой на странице (секунды, раздел 8.1) или командой `lay place=…` (минуты, полный перебор). Пять финалистов в `boards/`; у команды — отчёт воронки. Отчёт читает агент; если находки меняют бриф («на этом поле без проката такой доски нет»), он говорит это владельцу до игры — как вопрос о брифе, а не как пересказ досок.
3. **Игра.** Владелец открывает `?lab=levels`, выбирает место и жмёт «от замысла» — или открывает готовую `?lab=levels&board=K31-1a` и идёт по буквам. Доска стоит вслепую, `E` — играть, «ещё» — следующая. Голый адрес `?board=` партию не записывает и об оценке не спрашивает, поэтому для круга он не годится.
4. **Отметки.** После партии — клавиши, которые уже есть (лаборатория, раздел 12): `1` огонь, `2` норм, `3` мимо, `U` новое, `M` ещё. Первая ставит статус файла. Слова сверх клавиш он говорит в чате; агент записывает их дословно на страницу места (ключ акта) или в [VI_Owner_Words.md](../../VI_Owner_Words.md).
5. **Следующий круг.** Номер круга растёт на единицу. Если две доски подряд на этом месте получили «мимо», выдача останавливается: страница говорит «два мимо подряд — спроси о замысле», команда кончается кодом `3`. Агент спрашивает владельца, что не так в самом замысле, и правит его; круг начинается заново.

### 8.1. Кнопка на странице: секунды

Слово владельца: «думаю секунды будут лучше». В папке «Генерация» — выбор места с замыслом и кнопка «от замысла». Устроено как заказ (`OrderDesk`, лаборатория, раздел 11): до четырёх воркеров, каждый со своей доли.

- Воркеры кладут раскладки не подряд, а в порядке, перемешанном по зерну: так первые годные доски приходят сразу и разной формы.
- Доска, прошедшая ступени 0–2, сразу встаёт на поле вслепую. По замерам прототипов годна одна раскладка из трёхсот, процесс кладёт около сотни в секунду: первая доска ждётся через 2–5 секунд. В браузере это число замеряет план.
- Пока владелец играет, поиск идёт дальше и держит запас; третья ступень считается в фоне у досок запаса. «Ещё» берёт из запаса лучшую по форме и по отметкам. Доска, показанная до своей третьей ступени, получает паспорт позже; ворот третьей ступени она могла не пройти — это пишется в паспорт, а не прячется.
- Круг — пять досок; после пятой страница говорит, что круг кончен, и «ещё» начинает следующий.
- Доски пишутся теми же файлами, что у команды.

Цена секунд: страница видит сотни раскладок, а не всё пространство, и не говорит «такой доски нет». Если за десять секунд годной доски нет, она показывает ближайшую с тем, чего та не держит, и советует команду `lay`. Полный перебор, отчёт воронки и отрицательные находки — только у команды.

### 8.2. Как следующая кладка использует отметки

Три хода, от механического к ручному.

- **Порядок финалистов.** Отметки сводятся с паспортами по хешу версии. У каждой доски, прошедшей вторую ступень, считается расстояние до ближайшего «огня» и до ближайшего «мимо» по мерилам паспорта, приведённым к одной шкале (`par`, `turns`, `away`, `quiet`, `firsts`, доля костей с гранью на виду, `last`, число костей, значения уроков). Доски идут от близких к «огням»; форма, отмеченная «мимо», и доска, которую он уже играл, не выдаются. Берутся оценки этого места, а если их меньше пяти — всех мест того же акта.
- **Правка замысла.** Слова владельца меняют сам замысел: «не вижу, куда катить» — `starts` и `open`; «слишком просто» — перекат или кость сверх; «ловушка нечестная» — глубина приманки. Это делает агент; команда тут только быстро отвечает, бывает ли такая доска. Версии замысла хранит git, слова — документы.
- **Сводка.** `ratings` получает мерила паспорта (тот же стык по хешу) и показывает «огонь против мимо» по каждому. Отсюда агент берёт полосы для следующих мест.

Это сравнение, а не модель: оценок десятки, и подгонка весов по ним была бы самообманом. Так уже сказано о `ratings` в лаборатории.

Оценки лежат в `boards/.history/` того worktree, чей дев-сервер играл, и в git не входят. Кладка следующего круга идёт в том же worktree; план называет его и говорит, как перенести историю, если worktree сменился.

## 10. Что боты не различают

Торопливый и обычный почти не проходят ни одну доску со спрятанной гранью: на местах 18–21 они дают 0,00–0,20, планирующий — 0,47–1,00 при любой роли. По ботам самая трудная доска акта II — твист, а не пик, и сразу за ним стоит самая лёгкая. Роли внутри акта (применение, твист, соединение, пик) лаборатория не различает.

Причина в устройстве персон: они смотрят на один–пять ходов вперёд и ценят доску по числу стоящих костей. Перекат, который ничего не снимает, но поднимает нужную грань, для короткого взгляда не лучше любого другого. Человек тут не считает ходы, а узнаёт инвариант кости (спека кампании, раздел 5.2).

Слово владельца 13 октября: «конечно да, мне нужен мощный и качественный генератор и боты его часть». Бот входит в работу.

### 10.1. Персона, которая читает кость

Пятая персона в `src/rules/levelBot.ts`, рабочее имя `reader`. Правил уровня она не касается; четыре нынешние персоны не меняются, их числа в документах остаются сравнимыми.

- **Чем отличается.** Нынешние ценят доску по числу стоящих костей. Читающая добавляет к цене то, что знает человек, усвоивший инварианты кости: для каждой стоящей кости — сколько перекатов нужно, чтобы она встала рабочей гранью вверх рядом со своей группой. Это поиск одной кости по свободным клеткам (не больше 24 положений на клетку), а не всей доски, поэтому он дёшев.
- **Что это даёт.** Перекат, который ничего не снимает, но приближает грань к верху, становится для неё лучше прочих. Глубина взгляда по доске остаётся малой (два хода, как у обычного): разница между досками должна идти от чтения кости, а не от перебора.
- **Что она не знает.** Время (два хода ухода, запас звена) и порядок событий — только в пределах своей глубины. Иначе она станет планирующим и снова перестанет различать.
- **Сверка.** Мерило годно, если на двенадцати досках актов I–II её доля прошедших (а) лежит между обычным и планирующим, (б) различает доски: не все около нуля и не все около единицы, (в) идёт в ту же сторону, что слова владельца о трудности этих досок, когда он сыграет акты. Пока (в) нет, её число — строка паспорта; воротами в замысле оно становится после.
- **Цена.** Ещё одна персона в отчёте ботов: третья ступень дорожает примерно на четверть.

Точные веса и параметры — в плане сборки, по замеру на досках актов.

### 10.2. Что ещё делается

1. Полы нынешних персон у мест со спрятанной гранью не ворота, а строка паспорта (решение 11). Ворота остаются там, где они работают: передышки и открытые доски (`K22`, `K28`: 0,90 и выше).
2. До сверки читающей персоны порядок досок по трудности внутри акта — паспорт (`turns`, `away`, `quiet`, `firsts`, доля граней на виду, сцепка) и игра владельца.
3. `ratings` с мерилами паспорта (раздел 8.2) через несколько кругов покажет, какое из мерил идёт вместе с его «трудно» и «огонь». До этого ни одно не объявляется мерой трудности.

## 11. Что не входит

- Правки правил уровня, решателя и партитуры в `src/rules`; нынешние четыре персоны.
- Модель трудности из оценок.
- Панель замысла на странице `?lab=levels`: замысел пишет агент в рецепте места, на странице только выбор места и кнопка. Заказ с панели (`order`) остаётся как есть.
- Обучение на оценках сверх порядка финалистов.
- Откаты через пол и подъём по уходящим: кладка назад знает перекат и толчок, остальное находит проверка вперёд.
- Замыслы с приходом костей, пределом ходов, особыми костями.
- Поля больше 5×5.
- Перевод `repair` и `improve` на замысел (функция суда строится так, чтобы это было возможно).
- Постройка актов III–V и урок проката по уходящей кости: это работа кампании, генератор — её инструмент.
- Правка `Scene`, `layFromRoute`, `judge`, `gen`, `order` и формата файла доски.
