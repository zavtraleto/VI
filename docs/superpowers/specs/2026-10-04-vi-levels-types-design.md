# VI — уровни, вторая проба: типы уровней

Дата: 4 октября 2026 · Статус: принята владельцем («давай сделаем»), собрана в тот же день; что при сборке вышло иначе — раздел 12. После плейтеста в тот же день девять уровней пробы из списка убраны: игра строится на очистке, список — первые двадцать уровней (`src/levels/levels.ts`); цели `send`, `order`, `chain` и приход костей остались в правилах с тестами. Исполнитель: Opus. Область: `src/rules`, `src/levels`, `src/app`, `src/shell`, `src/input`, `src/render`, `scripts`.

Исполнителю хватает этой страницы и названных в ней файлов. Откуда решения: [VI_Levels_Constraints.md](../../VI_Levels_Constraints.md) (варианты, числа ботов, ответы владельца). Первая проба: [2026-10-04-vi-levels-probe-design.md](2026-10-04-vi-levels-probe-design.md); её код лежит незакоммиченным в этом же рабочем дереве, и вторая проба правит его.

## 1. Что решено

| Вопрос | Решение |
|---|---|
| Луп и уровни | Луп один. Уровни трёх типов: **очистка**, **комбинация**, **цепочка**. Тип задают цель, старт и приход |
| Ход | Без изменений: перекат или толчок. Шаги с кости на кость бесплатны и мир не двигают |
| Стекло | Уходящая кость — стекло сразу: по ней можно прокатиться и толкнуть через неё кость с первого же хода. Кость под игроком твёрдая, пока он на ней |
| Приход | Свойство уровня: `none` или `refill` (добор до нормы, как в первой пробе). Долю костей «для цепочки» задаёт уровень |
| Показ прихода | Кость встаёт на свою клетку стеклом в полвысоты сразу, как объявлена, и стоит так всю паузу; за следующий ход поднимается. Знака-предупреждения на уровне нет |
| Отмена | Только на уровнях без прихода: бесплатная, сколько угодно ходов назад |
| Лимит ходов | Очистка — без лимита, ходы считаются вверх. Остальные — от бота, знающего цель; не больше 40 |
| Тупик | На очистке игра говорит, когда осталась одна стоящая кость и нет открытой группы |
| Цель на экране | Карточка на языке игрока перед уровнем; в шапке — грань картинкой и счёт; при проигрыше — чего не хватило. Вид временный |
| Управление на уровне | Шаг делается, когда палец отпущен; стрелка на поле показывает прочитанное направление. Удержание шагов не повторяет |
| Проба | Девять уровней, по три каждого типа, вперемежку, от элементарного к трудному. Адрес прежний: `?levels` |
| «Напор», «каждый шаг — ход» | Отложены |

Endless, сеанс дня, обучение и пазлы не меняются: их тесты не правятся, `RULES_VERSION` остаётся `0.9`. Правило стекла включается только на уровне; в остальные режимы — после плейтеста.

## 2. Правила: что меняется

### Типы

```ts
// src/rules/types.ts
export type LevelGoal =
  | { kind: 'send'; count: number }
  | { kind: 'order'; items: readonly { value: number; count: number }[] }
  | { kind: 'chain'; links: number }
  | { kind: 'clear' }; // no die left standing

export interface LevelSpec {
  id: string;
  seed: number;
  size: number;
  goal: LevelGoal;
  /** Limit of moves; 0 for none. */
  moves: number;
  values: readonly number[];
  /** Dice the board starts with; with `refill`, the number it is kept at. */
  norm: number;
  /** Whether dice come: `none`, or `refill` back to `norm`, one a beat. */
  arrival: 'none' | 'refill';
  /** Share of the dice that come for a running chain; the rules' own when left out. */
  feedRate?: number;
  helpRate?: number;
  sinkMoves?: number;
  liftMoves?: number;
}

/** What a line of a goal counts: dice of any face, dice of one face, links of a chain, dice cleared off the board. */
export type GoalWhat = 'dice' | 'face' | 'links' | 'cleared';
export interface GoalLine { what: GoalWhat; value: number; have: number; need: number }
```

`GoalLine` переезжает из `src/shell/text.ts` в `src/rules/types.ts`; `value` значим только у `face`. Числовое кодирование первой пробы (0 и −1) уходит.

### `src/rules/level.ts`

- `LEVEL_WARN_TICKS` убрать. Добавить `LEVEL_GHOST_HEIGHT = 0.5`.
- `levelConfig`: `warnTicks: 0`; `risingTicks: actionTicks / (1 − LEVEL_GHOST_HEIGHT)` (20); `sinkLowHeight: 1`; `stepDownHeight: 1`; `feedRate: spec.feedRate ?? config.feedRate`. Остальное как было.
- `goalLines(state: RunState): GoalLine[]` и `goalReached(state)` берут состояние, а не `LevelRun`: очистке нужно поле. Для `clear`: `{ what: 'cleared', value: 0, have: norm − стоящих, need: norm }`, где стоящие — кости не в `sinking`. `have` по-прежнему не больше `need`.
- `goalOf(spec: LevelSpec): GoalLine[]` — цель до первого хода, с `have: 0`: для списка и карточки.
- `levelStuck(state): boolean` — цель `clear`, уровень не кончен, стоит ровно одна кость и `state.reactions` пуст. Такую кость уже не убрать.
- `endBeat`: добор только при `spec.arrival === 'refill'`.

### `src/rules/spawn.ts`

- `refillLevel`: кость не объявляется, а ставится сразу: `spawnCube(...)`, затем `cube.t = risingTicks − actionTicks`. Так она стоит стеклом в полвысоты всю паузу и встаёт в конце следующего такта. `state.pending` на уровне всегда пуст.
- `placeLevelLayout`: 400 попыток вместо 100 — плотные поля очистки кладутся реже.

### Что следует из стекла

`sinkLowHeight: 1` значит: клетка с уходящей костью для переката и толчка открыта всегда. Со стоящей кости шаг в сторону уходящей — это перекат через неё (ход), а не шаг на неё. С уходящей кости на уходящую и на стоящую — шаг, как раньше. Кость, по которой прокатились, снимается с поля; в цель она уже засчитана.

### Тесты правил

`src/rules/level.test.ts` — файл первой пробы, правится под новые правила:

- конфиг: `warnTicks 0`, `risingTicks 20`, `sinkLowHeight 1`, `feedRate` уровня;
- приход: после ухода группы кость стоит стеклом (`rising`, высота 0,5) сразу в тик посадки; к концу следующего такта она `idle`; `pending` пуст; по ней можно прокатиться, и она переезжает в ближайшую свободную клетку;
- между ходами на поле только стоящие кости, уходящие и кости прихода в полвысоты;
- `arrival: 'none'`: после ухода группы ничего не приходит, сколько бы ходов ни прошло; игрок на полу без пути наверх кости под ноги не получает;
- стекло: перекат в клетку группы, собранной ходом раньше, принят и снимает её кость; та же грань продолжает цепочку;
- `clear`: уровень пройден в тик, когда встала в группу последняя стоящая кость; `goalLines` считает убранные; `levelStuck` верно на одной кости без открытой группы и ложно, пока группа открыта;
- остальные тесты первой пробы (мир стоит, ход, окно группы, цели, лимит, свободный такт, детерминизм) остаются и проходят.

## 3. Бот, знающий цель

`src/rules/bot.ts` — два необязательных поля, без них бот играет точно как раньше (его тесты не правятся):

- `Plan.value?: number` — грань очистки, которой кончается план (1 для единицы); заполняет `worth`;
- `Bot.prefer?: (plan: Plan, state: RunState) => number` — вес плана, 0 отбрасывает. Применяется в `decide` после отбора по `sight` и не трогает генератор бота.

`src/rules/levelBot.ts`:

- `goalBot(spec, skill, botSeed): Bot` ставит `prefer` по цели: `order` — грань из невыполненных строк весит 1, прочие 0,1; `chain` — пока есть открытая группа, план со звеном весит 1, прочие 0,1; `send` и `clear` — без предпочтений.
- `playLevel(spec, skill, botSeed, maxMoves = 150)` играет таким ботом. `LevelPlay` получает `left` — костей осталось стоять.
- `levelTable`: те же колонки плюс «осталось костей, медиана» для очистки. С `seeds=N` — по каждому сиду медиана `average` и доля дошедших.

Правила подбора, руками ничего не выдумывается:

1. **Сид.** Из сидов 1…24 берутся те, где поле кладётся и до цели доходит хотя бы один прогон `pro` или `esports` с `botSeed` 1…10. Среди них — сид со средней медианой `average` (при чётном числе — нижняя из двух средних). У очистки вместо медианы ходов — доля прогонов `average`, очистивших поле.
2. **Лимит** (кроме очистки): `ceil(медиана average × 4 / 3)`. Если вышло больше 40 или `average` доходит реже чем в половине прогонов — уровень слишком длинный: цель уменьшается на шаг (меньше костей, короче цепочка), и это отмечается в отчёте.
3. Итоговая таблица прикладывается к отчёту.

`scripts/levels.mjs` — прежние аргументы.

## 5. Приложение и интерфейс

### `src/app/game.ts`

- **Карточка цели.** `startLevel(index, { card })`: из списка и по NEXT уровень открывается карточкой; START с неё начинает игру. «Заново», AGAIN и клавиша R карточку не показывают.
- **Отмена.** На уровне с `arrival: 'none'` перед каждым перекатом и толчком состояние кладётся в `history`, как у задач (`beforeCommand`, `structuredClone`). `undoLevel()` возвращает последнее; клавиши Z и Backspace; кнопка в углу поля. Отмены считаются в `LevelStat.undos`.
- **Шапка.** `goalLines(state)`; при `moves: 0` — число сделанных ходов.
- **Строка под полем.** По порядку: тупик (`levelStuck`, тревожным тоном) → уходящие группы → подсказка.
- **Итог.** При проигрыше — строка голосом, чего не хватило.
- **Ввод.** В `begin()`: `controller.setRepeat(!state.levelRun)`; жесты на уровне — с фиксацией на отпускании.

### `src/input`

- `controller.ts`: `setRepeat(on: boolean)`; при `false` удержание не повторяет шаг. По умолчанию `true`: остальные режимы без изменений.
- `gesture.ts`: `GestureTracker` получает четвёртый необязательный аргумент `onRelease: () => boolean`. Пока он даёт `true`: `move` только читает направление (с тем же гистерезисом и мёртвой зоной) и ничего не посылает; `up` посылает один шаг в прочитанную сторону, если она есть; возврат пальца в мёртвую зону снимает направление — шага не будет. Стрелку на поле уже рисует `steerGuide` по `tracker.direction`.
- Тесты — новый файл `src/input/release.test.ts`: отпускание даёт один шаг; возврат к началу — ни одного; поворот пальца меняет прочитанное направление без шага; удержание при `setRepeat(false)` не повторяет; без нового аргумента поведение прежнее.

### `src/shell`

- `text.ts`: `GOAL = { dice: 'SEND', links: 'CHAIN', cleared: 'LEFT' }`; `goalProgress` и `goalText` — по `GoalLine.what`; у `cleared` показывается остаток: `LEFT 05`.
- `hud.ts`: `HudLevel` получает `made: number`. Строка цели `face` — грань картинкой (`kit.face`, как счётчик урока в `drawLesson`) и счёт; прочие — слово из `GOAL` и счёт. При `left === null` крупное число — `made`. `tools`: на уровне без прихода — обе кнопки, `urgent` при тупике; с приходом — `retryOnly`.
- `panels.ts`: `levelGoalPanel({ number, lines }, { onStart, onBack })` — строки голосом (`say`), команды START и BACK; `levelResultPanel` получает `reason?: string` — строку голосом над полями.
- `src/ui/i18n.ts`, ru и en:

| Ключ | ru |
|---|---|
| `levelGoalSend` | Отправь кости. Нужно: {count} |
| `levelGoalOrder` | Отправь кости с этим числом сверху. {items} |
| `levelGoalChain` | Собери цепочку. Звеньев: {links}. Звено — группа или кость, добавленная к уходящей группе |
| `levelGoalClear` | Убери с поля все кости. Новые не придут |
| `levelGroups` | Кости уходят группой: две двойки рядом, три тройки, четыре четвёрки |
| `levelMoves` | Ходов: {moves}. Ход — перекат или толчок; шаг с кости на кость хода не тратит |
| `levelNoLimit` | Ходы не ограничены. Ход можно отменить |
| `levelStuck` | Тупик: одна кость не уйдёт. Отмени ход или начни заново |
| `levelShort` | Ходы кончились. Не хватило: {short} |

`{items}` собирается как `«2» — 4, «3» — 6`. Карточка: строка цели, `levelGroups` на первых трёх уровнях, затем `levelMoves` или `levelNoLimit`.

### `src/render/cubes.ts`

В `look()`: на уровне уходящая кость под игроком рисуется как `sinking`, а не `sinkingLow` — она твёрдая, пока он на ней. Остальные уходящие при `sinkLowHeight: 1` сами получают вид низкой кости.

### `src/platform/settings.ts`

`LevelStat.undos: number`; у сохранённой статистики без поля — 0. Отчёт `levelReport` добавляет `undos N` и для уровня без лимита пишет `no limit`.

## 8. Проверка

`npm test`, `npm run typecheck`, `npm run build`, `node scripts/levels.mjs`.

В браузере по адресу `/?levels`. Панель превью приложения, когда скрыта, даёт около кадра в секунду: сценарии прогонять в Chrome через DevTools на том же дев-сервере (`vi-dev`, порт 5183), команды подавать скриптом в странице.

- карточка цели на трёх типах; очистка: пройти, зайти в тупик, отменить ход, «заново»;
- комбинация: пройти и проиграть, причина в итоге;
- цепочка: кость прихода видна стеклом до хода; прокатиться по ней;
- стекло: перекат через кость группы сразу после сбора;
- ширина телефона: свайп с отпусканием даёт один шаг, возврат пальца — ни одного;
- обычный адрес открывает меню; сеанс дня играется как раньше, удержание там повторяет шаг.

## 9. О что можно споткнуться

- `goalLines` меняет аргумент: `game.ts`, `levelStats.ts` (`shortOf`), `levelBot.ts`, тесты.
- Отмена возвращает состояние целиком, вместе с `rng`: на уровне без прихода генератор после старта не тратится, так что отмена ничего не подсматривает.
- `spawnCube` поднимает игрока, если кость встала под ним: лифт на уровне с добором работает как раньше.
- На уровне без прихода игрок на полу может остаться без пути наверх, пока не толкнёт кость к краю. Это не тупик: толчок — ход.
- `Bot.prefer` нельзя вызывать до отбора по `sight`: порядок обращений к генератору бота должен остаться прежним.
- Статистика первой пробы лежит под ключами `p01`…`p08`; новые ключи другие, старые в отчёт не попадают.

## 10. Готово, когда

- По `?levels` девять уровней трёх типов; каждый открывается карточкой с целью словами.
- На очистке ничего не приходит, ход отменяется, тупик назван.
- Кость прихода видна на клетке до хода; по кости группы можно прокатиться сразу.
- На телефоне один свайп — один шаг, и только после отпускания.
- Лимиты и сиды взяты из таблицы; ни один лимит не больше 40.
- Тесты, типы и сборка проходят; тесты прежних режимов не менялись. Ничего не закоммичено.

Показать владельцу: адрес; таблицу ботов по девяти уровням; что сделано иначе и почему; на что смотреть в плейтесте — понятна ли цель с карточки, хватает ли показа прихода, думается ли на очистке, помогает ли приход цепочке, слушается ли свайп.

Замечания владельца к спеке: очистку сделать решаемой; по несколько уровней на тип; шаг с группы на целую кость — обязательство, его сохранить, связать с логикой мира и отметить эффектом.

| Что | Как в спеке | Как сделано и почему |
|---|---|---|
| Свободный такт | только когда не стоит ни одной кости | ещё и когда игрок стоит на кости, которая приходит: с неё нельзя ни сойти, ни перекатить, и без этого игрок, зашедший на неё с пола, застревал навсегда |
| `k2` | 5×5, «3 тройки и 4 четвёрки» | 7×7, 14 костей, «6 троек»: на малом поле бот шёл к прежней цели 88 ходов |
| `k3` | 7×7, грани 2 и 3 сверху, «4 четвёрки», которых сверху нет | 7×7, грани 2–4, 18 костей, «3 тройки и 4 четвёрки». Цель с гранью, которой нет сверху, бот не проходит и по запасному варианту: он не строит группу в несколько ходов, и лимит поставить нечем. Нужен бот-планировщик — следующая задача |
| Бот, знающий цель | одно поле `prefer` | ещё `wants`: без очистки в поле зрения он охотнее поворачивает кость нужной гранью вверх. Без обоих полей бот играет как раньше |
| Строка под полем | тупик → уходящие группы → подсказка | тупик → подсказка → уходящие группы: подсказка об обязательстве звучит как раз тогда, когда группа уходит, и за её строкой была бы не видна |
| Обязательство | не названо | рамка на кости, на которую шагнули, и разовая подсказка `hintCommit`; строки в «Логике мира» с предложениями причины |
| Статистика | `undos` | ещё `bestMoves` — за сколько ходов уровень пройден: на очистке остатка ходов нет |
| Решаемость очистки | свидетель-бот | так и сделано: в пробу попали только сиды, которые бот очищает до последней кости; тест уровней этот прогон повторяет |
