## Цель

Один канвас и один рендерер на всё приложение, изображение собирается из слоёв. Поверх этого — набор PS1-приёмов, страница-лаборатория и одна генеративная сцена «море и столб» (IMAGE 0001), которую пользователь настраивает сам.

Вид и поведение игры после этой работы **не меняются**: поле рисуется как раньше, только через новый пайплайн.

## Не входит

- Показ передач в потоке игры, boot, меню, перенос HUD и экранов из DOM.
- Смена палитры поля, кубов, фигуры. Контакт. Звук.
- Автомат экранов в `game.ts`.

Это подпроекты 1–5; здесь для них закладывается только основа.

## Принципы

- Агент не придумывает внешний вид. Стартовые значения сцены нейтральные и скромные; картинку доводит пользователь ползунками в лаборатории.
- Сцена — код с параметрами и сидом. Никаких файлов-ассетов: геометрия, текстуры и цвета строятся программно. Один и тот же сид и параметры всегда дают один и тот же кадр.
- `src/rules` не трогаем.

## Архитектура

Новая папка `src/display/`:

| Файл | Что делает |
|---|---|
| `display.ts` | `Display`: единственный `THREE.WebGLRenderer` и канвас на всё окно; список слоёв; `present()` выводит слои на экран по порядку |
| `layer.ts` | `Layer` — текстура-цель на всё окно со своим разрешением; `CanvasLayer` — слой, нарисованный через Canvas2D |
| `present.ts` | Шейдер вывода слоя: перевод в sRGB, дизеринг, глубина цвета, инверсия, прозрачность |
| `ps1.ts` | `ps1Material()` — материал сцен-передач |
| `sizing.ts` | Чистые функции размеров (тестируются без WebGL) |

### Display

```ts
class Display {
  readonly renderer: THREE.WebGLRenderer;
  /** Размер окна в CSS-пикселях. */
  readonly width: number;
  readonly height: number;
  constructor();                       // создаёт канвас, ставит первым в document.body
  addLayer(options: LayerOptions): Layer;
  addCanvasLayer(options: LayerOptions): CanvasLayer;
  removeLayer(layer: Layer): void;
  /** Собирает видимые слои на экран в порядке добавления. */
  present(): void;
}
```

Канвас: `position: fixed; inset: 0`, под `#app`. Свой цикл `Display` не ведёт: `present()` вызывает тот, кто владеет кадром (игра или лаборатория).

### Layer

```ts
interface LayerOptions {
  name: string;
  /** Высота цели в пикселях; ширина — по пропорции окна. null — высота окна × pixel ratio (не больше 1.5). */
  lines: number | null;
  /** MSAA для чётких слоёв. */
  samples?: number;
  look?: Partial<LayerLook>;
}

interface LayerLook {
  opacity: number;              // 0 — слой не выводится
  depth: number;                // бит на канал после квантования; 8 — выключено
  dither: number;               // 0..1, упорядоченный дизеринг 4×4 перед квантованием
  invert: boolean;
  filter: 'nearest' | 'linear'; // как слой растягивается на экран
}

/** Прямоугольник в CSS-пикселях от верхнего левого угла окна. */
interface Rect { x: number; y: number; width: number; height: number }

class Layer {
  look: LayerLook;
  setLines(lines: number | null): void;
  /** Рисует сцену в слой. rect — часть окна в CSS-пикселях; без него — всё окно. */
  render(scene: THREE.Scene, camera: THREE.Camera, options?: { rect?: Rect; clear?: THREE.Color }): void;
}

class CanvasLayer extends Layer {
  readonly ctx: CanvasRenderingContext2D;
  /** Текстура перезаливается только после этого вызова. */
  markDirty(): void;
}
```

Вывод слоёв — по одному полноэкранному проходу на слой с альфа-смешиванием. Общий шейдер смешивания миров появится в подпроекте CONTACT; сейчас его не делаем.

Дизеринг и квантование считаются в сетке пикселей самого слоя, а не экрана: при `lines: 240` точки дизеринга крупные.

### Поле через Display

`BoardView` ([src/render/view.ts](../../../src/render/view.ts)) перестаёт владеть рендерером:

- конструктор получает элемент `.stage` и слой `world` вместо создания `WebGLRenderer` и канваса;
- `resize()` берёт размеры и положение из `stage.getBoundingClientRect()`; кадрирование (`fitBoard`) не меняется;
- `draw()` вместо `renderer.render` вызывает `layer.render(scene, camera, { rect, clear: background })`; инверсия фазового сдвига — через `layer.look.invert`, а не CSS-фильтр;
- `project()` по-прежнему возвращает CSS-пиксели внутри `.stage`.

`Game` ([src/app/game.ts](../../../src/app/game.ts)) создаёт один `Display` и слой `world` (`lines: null`, `samples: 4`, без дизеринга). `useView` больше не переключает канвасы — выбирает активную доску. В конце `frame()` — `display.present()`. Стиль `.board-canvas` и связанный с ним комментарий убрать.

### PS1-материал

`ps1Material({ color?, map?, vertexColors?, fog, snap, light })` — `ShaderMaterial`:

- привязка вершин к сетке `snap` (дрожание геометрии);
- аффинное наложение текстуры; в GLSL ES 3.0 нет `noperspective` — умножать UV на `w` в вершинном шейдере и делить во фрагментном;
- освещение по вершинам: один направленный свет и рассеянный;
- линейный туман до цвета `fog.color` между `fog.near` и `fog.far`;
- текстуры — `NearestFilter`, без мипмапов.

Низкое разрешение, глубина цвета и дизеринг — свойства слоя, а не материала.

### Сцены

Новая папка `src/signal/`:

```ts
// scene.ts
type ParamSpec =
  | { kind: 'number'; value: number; min: number; max: number; step: number }
  | { kind: 'color'; value: string }
  | { kind: 'boolean'; value: boolean };

/** Значение каждого параметра по его имени. */
type ParamValues = Record<string, number | string | boolean>;

interface SceneDef {
  id: string;                                        // 'sea_pole'
  params: Record<string, ParamSpec>;                 // значения по умолчанию и диапазоны
  variants: Record<string, Partial<ParamValues>>;    // 'a', 'b': отличия от умолчаний
  build(values: ParamValues, seed: number): SceneInstance;
}

interface SceneInstance {
  scene: THREE.Scene;
  camera: THREE.PerspectiveCamera;
  update(timeMs: number, aspect: number): void;
  dispose(): void;
}
```

- `scenes/index.ts` — реестр `SCENES`.
- Общие параметры вида есть у каждой сцены (`LOOK_PARAMS` в `scene.ts`): `lines` (120–480, по умолчанию 240), `depth` (3–8, по умолчанию 5), `dither`, `snap`. Лаборатория переносит их в слой.
- При изменении любого параметра или сида сцена пересобирается целиком: сцены маленькие. Время при этом не сбрасывается.
- Случайность — `nextRandom` из [src/rules/rng.ts](../../../src/rules/rng.ts) с держателем `{ rng: seed }`. `Math.random` в сценах не использовать.

### Сцена `sea_pole`

Файл `src/signal/scenes/seaPole.ts`. Содержание: светлое море до горизонта, небо, одиночный телефонный столб.

- Небо: градиент от `skyTop` к `skyHorizon`.
- Море: сетка с волнами по вершинам (сумма двух-трёх синусов, фазы от сида); цвет `sea`; уходит в туман цвета горизонта.
- Столб: стойка квадратного сечения, перекладины, изоляторы-коробочки, лёгкий наклон.
- Провода: провисающие линии от перекладин за край кадра.
- Камера неподвижная, с необязательным медленным дрейфом.

Параметры: `skyTop`, `skyHorizon`, `sea`, `poleColor`, `fogNear`, `fogFar`, `poleHeight`, `poleTilt`, `poleX`, `crossarms`, `wireSag`, `wireUnderwater`, `waveHeight`, `waveSpeed`, `camHeight`, `camDistance`, `camFov`, `camPitch`, `drift`, `lightAngle`, `lightAmount` и общие параметры вида.

Варианты: `a` — умолчания; `b` — `wireUnderwater: true`, один провод уходит под воду (IMAGE 0003).

Стартовая палитра — из раздела 2.3 арт-документа: молочный белый, серебристо-серый, ледяной голубой.

### Лаборатория

Новая папка `src/lab/`. Вход — в [src/main.ts](../../../src/main.ts): если в адресе есть `lab`, вместо `Game` динамически импортируется `./lab/lab`.

- Адрес: `?lab=sea_pole&variant=b&seed=3`. Без значения — первая сцена реестра.
- `Display` с двумя слоями: `signal` для сцены и `CanvasLayer` для подписи.
- Панель — `lil-gui` (новая зависимость, подгружается только в лаборатории). В ней: выбор сцены и варианта, сид и кнопка «следующий», все параметры сцены (ползунки, выбор цвета, флажки), поле `caption`.
- Кнопки: «Скопировать параметры» — в буфер уходит JSON с id сцены, сидом и только теми значениями, что отличаются от умолчаний; «Сбросить».
- Подпись `caption` рисуется в `CanvasLayer` системным моноширинным шрифтом в нижнем левом углу. Шрифт временный: выбор шрифтов — подпроект PROGRAM.
- `&ui=0` прячет панель, чтобы смотреть кадр на телефоне.
- Для превью, где `requestAnimationFrame` не идёт: `window.lab.frame(timeMs)` рисует один кадр, как `window.vi.frame` в игре.

Лаборатория входит в обычную сборку: её нужно открывать с телефона на GitHub Pages.

## Подводные камни

1. **Цветовое пространство.** В текстуру-цель three.js пишет линейные значения; перевод в sRGB делает `present.ts`. Фон поля `#050506` в линейном виде меньше половины шага 8-битного канала и станет чисто чёрным — цель слоя `world` должна быть `HalfFloatType`.
2. **Сглаживание.** У рендера в текстуру нет сглаживания по умолчанию; у слоя `world` — `samples: 4`. `antialias` у самого рендерера больше не нужен.
3. **Прямоугольник слоя.** `rect` задан в CSS-пикселях от верхнего левого угла окна; viewport и scissor цели — в пикселях цели, от нижнего левого.
4. **Фон страницы.** `BoardView` по-прежнему выставляет CSS-переменную `--void`; слой `world` очищается этим же цветом на всё окно.
5. **Чужие правки.** В `src/render/view.ts` и `src/render/springs.ts` лежат незакоммиченные правки другого чата (подъём тонущих кубов в цепочке). Их сохранить; свои изменения в `view.ts` держать в конструкторе, `resize()` и последних строках `draw()`.
6. **Порядок кадра.** Сначала `view.draw()` рисует в слой, затем `display.present()`. Пока открыто меню, доска за ним продолжает рисоваться, как сейчас.

## Порядок работы

1. `sizing.ts` с тестами: размер цели по окну, `lines` и pixel ratio; перевод `rect` в viewport цели.
2. `Display`, `Layer`, `present.ts`. Проверка: пустой слой, залитый цветом, выводится без искажения цвета.
3. Перевод `BoardView` и `Game` на `Display`. Проверка: игра выглядит и работает как до правок — сравнить скриншоты до и после (меню, партия, обучение с текстом сверху, пазл с полем другого размера).
4. `ps1.ts`, `scene.ts`, `scenes/seaPole.ts` с тестом на слияние вариантов и на «отличия от умолчаний».
5. `CanvasLayer` и лаборатория.
6. Общая проверка и скриншоты для пользователя.

## Дополнение от 2 октября: движение, сигнал, подпись

Сделано после первого просмотра, по замечаниям пользователя и его референсу (кадр с красным солнцем над морем и субтитром).

**Движение в `sea_pole`.** Кадр не статичен при умолчаниях:

- камера плавает как с рук — `drift` (по умолчанию 0,35) и `driftSpeed`;
- провода качаются и дрожат — `wireTremble`, `wireSpeed`; у изолятора провод неподвижен;
- отблески на воде — `glint`, `glintColor`, `glintSize` (угловой размер блика в градусах), `glintWidth` (полуширина дорожки в градусах), `glintSpeed`. Дорожка лежит между глазом и светом, поэтому `lightAngle` по умолчанию теперь 165 (свет за столбом). Блики — опция `glint` у `ps1Material`, время идёт через его uniform `uTime`.

**Сигнал.** У `LayerLook` новые поля, все по умолчанию 0 (выключено): `blur`, `smear`, `chroma`, `glow`, `noise`, `scanlines`, `vignette`. Слой с ними выводится в три прохода: глубина цвета и дизеринг в текстуру размером со слой → размытие, смаз вдоль строк, расхождение цветов, свечение и шум в пикселях слоя → растяжение на экран со строками и виньеткой. Слой без эффектов (поле игры) выводится прежним одним проходом. `Display.present(timeMs)` — время нужно только шуму.

В `LOOK_PARAMS` те же поля и `smooth` (растяжение на экран мягкое или квадратами); `signalLook(values)` переводит значения сцены во внешний вид слоя.

**Подпись.** Субтитр, «вшитый» в кадр: светлые буквы с тёмным краем, по центру внизу, шрифт Forum (временно, до подпроекта PROGRAM). `|` — перенос строки, длинные строки переносятся сами. Слой подписи проходит тот же сигнал, но берёт 35% размытия, смаза и расхождения цветов, чтобы текст читался. На высоком окне у подписи больше строк, чем у сцены (`captionLines`), иначе в 111 пикселей ширины текст не помещается. Подпись можно задать в адресе: `&caption=...`.

**На потом.** Смена параметров на лету без пересборки сцены (чтобы картинка становилась тревожнее по ходу показа) — задача подпроекта SIGNAL v0.

## Дополнение 2 от 2 октября: комната, коридор, настроения

**Новые сцены** в том же стиле и тех же рамках (`SceneDef`, параметры, сид, общий вид слоя):

- `room_chair` (IMAGE 0002) — бетонная комната, стул повёрнут к пустой стене, голая лампа на шнуре. Вариант `b` (IMAGE 0006) — два стула занимают почти одно место (`twin`). Движение: камера, качание лампы, тень стула ходит за лампой, мерцание (`flicker`). Тень можно бросить не туда: `shadowTurn`, `shadowStretch`.
- `corridor_door` (IMAGE 0004) — пустой коридор, в конце светлая дверь. Вариант `b` — дверь почти закрылась (`doorOpen`). Движение: камера, медленный подход (`dolly`), мерцание ламп (`flicker`, `deadLamps`), створка двери ходит (`doorSwing`).

Свет в интерьерах — не в материале: он считается по вершинам каждый кадр и пишется в их цвета (`src/signal/surface.ts`), поэтому лампа может качаться и гаснуть. Общие части сцен — `src/signal/kit.ts` (камера «с рук», потоки случайности, процедурная текстура пятен).

**Настроения.** У каждой сцены пять пресетов по нарастанию тревоги: `dream` (светлая мечтательность, это умолчания сцены), `sad` (грусть), `strange` (странность), `anxious` (тревога), `fear` (страх). `SceneDef.moods` — отличия от умолчаний, как и варианты. Значения собираются так: умолчания ← вариант ← настроение (`sceneValues`). Вариант отвечает за то, что в кадре, настроение — за то, как это ощущается; настроения не трогают параметры, которые меняет вариант, поэтому любой вариант виден в любом настроении.

Лаборатория: список «настроение» в панели и `&mood=fear` в адресе.
