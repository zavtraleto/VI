# VI

Веб-игра по механическому ядру Devil Dice: перекатывай кубы, соединяй одинаковые верхние грани, продлевай цепочки. Основной режим — уровни (`LEVELS`): доска с заданной раскладкой костей, которую очищают за ходы. Второй режим — Endless (`PROTOCOL`): сессия без срока, кости приходят сами. Рабочее название.

- Правила уровней: [docs/VI_Levels_Rules.md](docs/VI_Levels_Rules.md)
- Правила Endless: [docs/VI_Endless_Rules.md](docs/VI_Endless_Rules.md)
- Планы: [docs/ROADMAP.md](docs/ROADMAP.md)
- Все документы, с видом и статусом каждого: [docs/README.md](docs/README.md)

Последняя сборка из `main`: https://zavtraleto.github.io/VI/ — выкладывается на GitHub Pages при каждом пуше.

На Playgama: https://playgama.ai/play/hbhtrqdwvr — sandbox, публичная ссылка без модерации.

## Запуск

```bash
npm install
npm run dev
```

Игра открывается на `http://localhost:5183`. Сервер слушает и локальную сеть, так что с телефона в той же Wi-Fi сети её можно открыть по адресу, который Vite печатает как `Network`.

```bash
npm test        # тесты правил, раннера, ввода
npm run build   # продакшн-сборка в dist/
npm run pack -- playgama   # сборка и архив для площадки: release/vi-<версия>-playgama.zip
npm run fonts   # пересобрать набор японских знаков после правки src/shell/text.ts
```

## Продакшн-сборка и платформа

- В продакшн-сборке нет инструментов разработки: лаборатории, панель плейтеста, дебаг-панель и счётчик кадров загружаются только под `import.meta.env.DEV`. Исключение — строки замера `?perf`: они грузятся в любой сборке, но только по адресу.
- Обфускация кода игры выключена: она добавляет 230 КБ к файлу игры и 0,2 мс к кадру. Включается явно: `VI_OBFUSCATE=1 npm run build` (`javascript-obfuscator`, настройки в [vite.config.ts](vite.config.ts)). three.js в любом случае лежит отдельным файлом `vendor`.
- Игра не знает ни одной площадки: она получает платформу из `@platform` и знает только тип `Platform` ([src/platform/platform.ts](src/platform/platform.ts)) — язык, сохранения, пауза и звук по событиям платформы, `game_ready`, реклама между сессиями, таблица игроков, аналитика. Площадка подставляется при сборке с `VI_PLATFORM`: её адаптер и файлы лежат в [platforms/](platforms/). Без неё — `none`, и сборка идёт без SDK и его файлов; дев-сервер, тесты и сборка для GitHub Pages — всегда `none`. Устройство и как добавить площадку — [спека](docs/superpowers/specs/2026-10-15-vi-platform-layer-design.md).
- Реклама: после сессии без срока — когда игрок уходит с итога и передача-ответ закончилась. Не чаще раза в 120 секунд, и никогда поверх игры.

Архив для Playgama — `npm run pack -- playgama`, он пишется в `release/vi-<версия>-playgama.zip` со скриптом Bridge SDK и его настройками. Кабинет, таблицы, токен и порядок выгрузки — [platforms/playgama/README.md](platforms/playgama/README.md).

## Журнал сеансов

Журнал — одна таблица, `プロトコル PROTOCOL`: вымышленные игроки, игроки платформы и строка самого игрока, по счёту. Собирает журнал [src/app/standings.ts](src/app/standings.ts). Сеанс дня (сессия на три минуты, `LIMITED`) убран из меню 4 октября 2026 (`d1a738b`), его код удалён 15 октября 2026 по слову владельца; достать — из истории git.

- **Вымышленные игроки** ([src/app/archive.ts](src/app/archive.ts)) — чтобы таблица новой игры не стояла пустой и выглядела живой. Их 250, у каждого своя сила и имя: у трёх четвертей — как у гостей площадки («Teal Otter», цвет и животное), у остальных — ники и имена. Счёт у всех настоящий: сессии сыграл игрок-бот разной силы. `node scripts/archive.mjs` играет их заново и пишет `src/app/archiveData.ts`; запускать после правки темпа или очков. Числа в файле сыграны 4 октября 2026; по правилам 15 октября скрипт даёт счёт заметно ниже — архив ждёт решения, пересчитывать ли его.
  - В журнале 4 октября 2026 стоят 50 из них, дальше каждые полдня добавляется ещё один, пока не войдут все.
  - Вымышленный игрок, которого зовут так же, как настоящего, в таблицу не попадает. На платформу эти строки не отправляются: они есть только в таблице, которую рисует игра.
- **Рекорды игрока** хранятся под ключом `endless` и не зависят от версии правил: с новой версией журнал и лучший счёт остаются. Раньше ключ включал версию правил, и после каждой новой версии список начинался с нуля. Рекорды сеанса дня (`timed`) снимаются со старых сохранений при загрузке.
- **Таблицы платформы** сервер ведёт отдельно для каждой площадки (`playgama_sandbox`, `playgama`): после выхода из песочницы таблица площадки начнётся с пустой, архив в игре остаётся.
- **Подъём по местам.** После сессии её счёт поднимается по журналу: счёт и место бегут, строки проходят мимо, у своего места движение замедляется ([src/shell/climb.ts](src/shell/climb.ts)). Образец — `?lab=shell&screen=climb&score=27770`.
- **Журналы сеансов вживую** (с 28 октября 2026). У каждой из семи ступеней сеанса свой журнал за всё время, по которому счёт поднимается в итоге сеанса так же: та же толпа вымышленных игроков, что в PROTOCOL, и строка игрока; игроков площадки в нём нет. Счёт вымышленных игроков в сеансе не сыгран ботом, а прикинут ([src/app/archive.ts](src/app/archive.ts), `liveArchive`): медианы пяти персон по замеру `pace.mjs` ступеней 1–3, для ступеней 4–7 — продолжение той же линии, у каждого игрока свой разброс.
- **`SHARE`** копирует строку со счётом и адресом игры (`gameUrl` площадки; в сборке без площадки адреса нет); на телефоне открывает системное «поделиться».

## Аналитика

События уходят через `platform.track` (на Playgama — `analytics.send` Bridge SDK), имена — как просит платформа (`progression_*`, `performance_sample`). Значения — только числа, строки и флаги; ничего об игроке.

| Событие | Когда | Что в нём |
|---|---|---|
| `progression_started` | начало сессии | `step_id`: `endless` |
| `progression_completed` | пройден уровень сессии (`endless_level`) | уровень: сколько длился, сколько костей пришло и ушло, сколько стоит на поле, счёт; сессия — сводка ниже |
| `progression_failed` | поле заполнено; игрок ушёл или начал заново (`reason`: `full`, `left`, `restart`, `skipped`) | сводка сессии |
| `progression_resumed` | игрок вернулся в партию, прерванную уходом со страницы | `step_id`, сколько секунд партия уже шла |
| `session_checkpoint` | каждая целая минута сессии | минута, счёт, уровень, костей на поле, убрано, длиннейшая цепочка, секунды в опасности |
| `performance_sample` | каждые 30 секунд игры | кадры активной игры: средний FPS, перцентили времени кадра, число долгих кадров, ошибки |
| `settings_changed`, `records_opened`, `player_registered` | настройка, журнал, вход | что изменено |
| `result_shared` | игрок поделился результатом | `mode`, `score`, `how` (`sent`, `copied`, `failed`) |
| `reward_double` | игрок досмотрел рекламу за удвоение счёта в итоге сеанса вживую (с 0.2.80) | `step_id`, `step_index` сеанса, `score` — удвоенный счёт |

Значения обучения Endless (`tutorial`, `tutorial_step`) и пазлов (`task`) ушли вместе с их кодом 15 октября 2026. У уровня `step_id` — `level_<id>`, например `level_P06`; в событиях попытки уровня (`progression_completed`, `progression_failed`) с 0.2.80 есть `hinted` — показан ли на этой попытке путь доски за рекламу.

Сеанс вживую (с 0.2.79): `step_id` — код сеанса `live-<ступень>` (`live-1` … `live-7`), `step_index` — номер места, после которого он стоит (с 0.2.85 — 16, 28, 43, 56, 71, 85, 92). `progression_started` — начало сеанса; `progression_completed` — сеанс дошёл до конца по часам, со сводкой сессии и `ticks`; `progression_failed` с `reason`: `full` — поле заполнилось раньше часов, `skipped` — ссылка «пропустить» в окне перед сеансом (только `step_id` и `step_index`), `left` — уход в меню, `restart` — заново из паузы. `session_checkpoint` и уровни сессии (`endless_level`) сеанс не шлёт.

Сводка сессии (по ней настраивается темп и приход костей): `rules` — ключ правил, `score`, `level`, `duration_sec`, `max_chain`, `best_chain_score`, `clears`, `removed`, `spawned`, `cubes_end`, `first_clear_sec`, `steps`, `blocked_steps`, `falls`, `ground_sec`, `floor_climbs` (подъёмы с пола на кость, которую нельзя толкнуть), `dock_descents` и `dock_climbs` (сходы с уходящей кости на клетку рядом с цепочкой и подъёмы с такой клетки на стоящую кость), `danger_sec`, `saves` (сколько раз поле уходило от опасной отметки), `chain_quiet_max_sec`, `match_2`…`match_6` (группы по числу на гранях), `ones`, `chains_2`, `chains_3`, `chains_4plus` (цепочки по длине), `contact`, `scored`, `best`. Считает [src/app/telemetry.ts](src/app/telemetry.ts).

В сводку сессии входят и показания, по которым сверяются боты ([src/rules/bot.ts](src/rules/bot.ts)): `drought_max_sec` (самое долгое ожидание очистки), `gifts` (подарки режиссёра), `clean_boards` (чистое поле), `wave` (до какой волны дошла партия). И то, что партия значит внутри визита: `run_index` (какая по счёту), `losses_in_row` (сколько партий подряд до неё кончились заполненным полем), `since_last_run_sec` (пауза после прошлой партии), `resumed` (партия продолжена после ухода со страницы), `control` (жесты или кнопки), `touch` (сенсорный экран).

Где смотреть: кабинет разработчика Playgama, раздел аналитики игры; агент читает те же данные через `get_game_telemetry_analytics`. Пока игра в статусе черновика, сводки там нет.

## Возврат в партию

Телефон выгружает страницу, которой не видно, и партия пропадала. Теперь партия Endless, от которой игрок ушёл, сохраняется (`vi.run.v1`, [src/app/savedRun.ts](src/app/savedRun.ts)): когда страница скрывается или закрывается, состояние партии кладётся в хранилище платформы. При следующем запуске игра открывается на паузе этой партии. Сохранённая партия снимается, когда партия окончена, брошена или начата заново; под другой версией правил не поднимается.

## Управление

- ПК: стрелки или WASD. ↑/W — от себя, →/D — вправо, ↓/S — к себе, ←/A — влево (с поправкой на поворот поля). Esc — пауза.
- Телефон: свайп вверх, вниз, вправо или влево — те же четыре направления, что у стрелок; удержание повторяет шаг. В панели плейтеста можно включить кнопки.

## Плейтест

Пауза → «Плейтест». Там переключатели экспериментов, выбор управления и статистика последней партии, которую можно скопировать текстом. Изменения правил применяются со следующей партии; рекорды ведутся отдельно для каждого набора правил.

Два правила пола включены по умолчанию и выключаются там же по отдельности: `floorClimb` — с пола на кость, которую нельзя толкнуть, поднимаются; `dockSteps` — клетки рядом с уходящей группой работают как ступени. Спека — [docs/superpowers/specs/2026-10-03-vi-floor-and-islands-design.md](docs/superpowers/specs/2026-10-03-vi-floor-and-islands-design.md).

### Дебаг-панель

Включается в панели плейтеста («Дебаг-панель переменных») или адресом `http://localhost:5183/?debug`, открывается кнопкой ⚙ в шапке. Ползунки геймплея применяются со следующей партии (кнопка «Заново»), углы камеры — сразу. Партия с изменёнными переменными в рекорды не пишется.

### Замер производительности

`?perf` в адресе показывает в углу строки, в любой сборке:

- кадров в секунду, 95-й процентиль и максимум промежутка между кадрами, число кадров дольше 33 мс, время кода кадра;
- переключений буфера и отрисовок на кадр, точек, залитых в видеокарту, число собранных шейдеров;
- первые секунды игры (`src/ui/perfFirst.ts`): самый поздний кадр и число кадров дольше 33 мс за 10 с после START (`start+10s`), самый поздний кадр и число собранных шейдеров за 0,6 с после первого хода (`move1 max … sh …`), под ними — замеры самой игры с именами `vi-` (звук `sound-open` и `sound-warm`, отложенный отчёт `start-said`, части кадра дольше 8 мс: `sim`, `board`, `wait`, `hud`, `present`; `rehearse`, если прогон картинки пришёлся на игру). То же из консоли: `viPerf.first()`;
- с каким качеством нарисована страница.

Качество задаётся там же, чтобы на телефоне увидеть цену каждой части картинки: `?perf&msaa=2`.

| Параметр | Значения | Что меняет |
|---|---|---|
| `msaa` | `0`, `2`, `4` | образцы сглаживания поля; без параметра игра начинает с 4 и сама убавляет качество, если устройство не держит 60 кадров, по ступени: сглаживание до 2, плотность холста до 1,25, ореол костей, плотность до 1, сглаживание до 0. Что держится полминуты — возвращается по ступени обратно; ступень помнится три дня |
| `auto` | `off` | игра не убавляет сглаживание, ореол и плотность холста сама |
| `ratio` | `0.5`–`3` (по умолчанию `1.5`) | предел точек холста на точку CSS; игра сама может опустить его ниже названного, если не сказано `auto=off` |
| `video` | `off` | слои идут на экран без размытия, расхождения цветов, свечения и зерна |
| `halo` | `off` | трубка не разносит свет вокруг костей поля: без малой картинки света и её размытия |
| `leak` | `off` | за полем ничего не просачивается |
| `water` | `off` | поле не лежит на воде (проба): без слоя воды, её кругов и отражения костей; за полем уровня рисуется прежнее место |
| `cap` | число (по умолчанию `60`), `0` — без предела | предел кадров в секунду на экране быстрее предела. Кадры пропускаются целыми, каждый второй, третий или четвёртый кадр экрана, чтобы шли ровно: на 120 и 240 Гц выходит 60, на 144 Гц — 72, на 60, 75 и 90 Гц рисуется каждый кадр |
| `patch` | `off` | слой-холст заливается в видеокарту целиком, а не изменившейся частью: проверка на случай, если браузер кладёт часть не на место |

Без параметров картинка и поведение обычные. Настройки читает [src/display/quality.ts](src/display/quality.ts).

### Вид поля на телефоне

Где клетка всей доски была бы мельче `minCell`, поле приближено, и экран показывает ту его часть, где стоит игрок: вид идёт за игроком по доске и не выходит за её край. Поле и кости при этом ровные, как при всей доске; остальная часть доски за краем экрана. Вид и его числа задаются в адресе, в любой сборке: `?view=follow&focus=0.6&followMs=250`.

| Параметр | Значения | Что меняет |
|---|---|---|
| `view` | `auto` (по умолчанию), `full`, `follow` | `auto` — по размеру клетки, настройке CAMERA в SYSTEM и уменьшенному движению; `full` и `follow` — вид назначен, что бы ни было; `follow` из адреса берёт масштаб прямо из `focus`, чтобы вид можно было смотреть на любом экране |
| `focus` | `0.3`–`1` (по умолчанию `0.6`) | наименьшая доля доски, которая помещается в экран: клетка крупнее, чем при всей доске, не больше чем в `1 / focus` раз |
| `minCell` | `0`–`120` (по умолчанию `64`) | размер клетки при слежении, в точках CSS: слежение включается, если клетка всей доски мельче, и увеличивает её до этого размера, но не сильнее `focus` |
| `followMs` | `0`–`1000` (по умолчанию `250`) | за сколько миллисекунд вид догоняет игрока; `0` — без догона |
| `edge` | `0`–`0.5` (по умолчанию `0.1`) | на какую долю экрана игрок не подходит к его краю, стоя у края доски; столько же экрана рядом с ним остаётся пустым. `0` — пустоты за краем доски не видно никогда, `0.5` — игрок всегда в центре |
| `lens` | `0`–`1` (по умолчанию `0` — выключена) | проба: линза поверх кадра. Поле и кости рисуются как есть, ровными, а их картинка сжимается к краям экрана, чтобы в кадр вошло больше доски, чем помещается; `1` — вся доска |
| `sharp` | `0`–`1` (по умолчанию `1`) | только с линзой: какую долю увеличения слой поля возмещает плотностью. `1` — картинка у игрока резкая, как без линзы; `0` — слой не плотнее холста, мягче и дешевле для видеокарты |

Читает [src/render/params.ts](src/render/params.ts) (`readView`); те же числа — в лаборатории `?lab=board`, папка «Вид».

## Структура

| Папка | Что в ней |
|---|---|
