# VI

Веб-игра по механическому ядру Devil Dice: перекатывай кубы, соединяй одинаковые верхние грани, продлевай цепочки. Рабочее название.

- Правила и исходная спецификация: [docs/RITE_Design_MVP.md](docs/RITE_Design_MVP.md)
- Что решено иначе: [docs/superpowers/specs/2026-10-01-vi-mvp-design.md](docs/superpowers/specs/2026-10-01-vi-mvp-design.md)
- Puzzle: [docs/superpowers/specs/2026-10-01-vi-puzzle-design.md](docs/superpowers/specs/2026-10-01-vi-puzzle-design.md)
- Планы: [docs/ROADMAP.md](docs/ROADMAP.md)

Последняя сборка из `main`: https://zavtraleto.github.io/VI/ — выкладывается на GitHub Pages при каждом пуше.

На Playgama: https://playgama.ai/play/hbhtrqdwvr — sandbox, публичная ссылка без модерации.

## Запуск

```bash
npm install
npm run dev
```

Игра открывается на `http://localhost:5183`. Сервер слушает и локальную сеть, так что с телефона в той же Wi-Fi сети её можно открыть по адресу, который Vite печатает как `Network`.

```bash
npm test        # тесты правил, раннера, ввода
npm run build   # продакшн-сборка в dist/
npm run pack    # сборка и архив для платформы: release/vi-<версия>.zip
npm run fonts   # пересобрать набор японских знаков после правки src/shell/text.ts
```

## Продакшн-сборка и платформа

- В продакшн-сборке нет инструментов разработки: лаборатории, панель плейтеста, дебаг-панель и счётчик кадров загружаются только под `import.meta.env.DEV`. Исключение — строки замера `?perf`: они грузятся в любой сборке, но только по адресу.
- Обфускация кода игры выключена: она добавляет 230 КБ к файлу игры и 0,2 мс к кадру. Включается явно: `VI_OBFUSCATE=1 npm run build` (`javascript-obfuscator`, настройки в [vite.config.ts](vite.config.ts)). three.js в любом случае лежит отдельным файлом `vendor`.
- Игра подключена к Playgama Bridge SDK: скрипт SDK ставит в страницу плагин `@playgama/bridge/vite` (с CDN, с копией в сборке на случай отказа CDN). Без платформы SDK работает в режиме заглушки, и игра идёт как обычно.
- Всё общение с платформой — в [src/platform/bridge.ts](src/platform/bridge.ts): язык, сохранения, пауза и звук по событиям платформы, `game_ready`, реклама между сессиями, таблица игроков, аналитика. Настройки SDK — в [public/playgama-bridge-config.json](public/playgama-bridge-config.json).
- Реклама: после сессии без срока и после сеанса дня — когда игрок уходит с итога и передача-ответ закончилась; в задачах — раз в 5–7 решённых, между двумя задачами. Не чаще раза в 120 секунд, и никогда поверх игры.

## Выкладка на Playgama

Игра в кабинете Playgama: `VI`, id `cmusa94kw028hpr0hzb9wqkrf`. Таблицы игроков: `endless` и `timed`. Публичный токен SaaS в [public/playgama-bridge-config.json](public/playgama-bridge-config.json) — это id игры, он не секрет.

Новая версия: поднять `version` в `package.json` (по ней различаются архивы в кабинете и сборки в аналитике), `npm run pack`, загрузить `release/vi-<версия>.zip` и опубликовать в sandbox через Playgama MCP (`start_archive_upload` → PUT → `confirm_archive_upload` → `get_archive_status` → `publish_sandbox`). Адрес sandbox при этом не меняется. Отправка на модерацию в основной каталог делается только руками в кабинете. Обложки в кабинете временные: кадры главного меню. Тексты страницы (описание и «как играть») — в [docs/VI_Playgama_Page.md](docs/VI_Playgama_Page.md).

## Сеанс дня

Сессия на три минуты (`LIMITED`) — сеанс дня: у всех игроков один сид на сутки по UTC, и своя таблица игроков на каждый день. Число дня и сид считает [src/app/daily.ts](src/app/daily.ts). Таблица платформы сама не обнуляется, поэтому счёт уходит в неё вместе с днём: `день × 1 000 000 + счёт`. Счёт сегодняшнего дня всегда выше любого прошлого, и верх таблицы — это таблица сегодняшнего дня; игра показывает только её.

### Журнал сеансов

В журнале две вкладки: `PROTOCOL` и `LIMITED`. В каждой — архив программы, игроки платформы и строка самого игрока, по счёту. Собирает журнал [src/app/standings.ts](src/app/standings.ts).

- **Архив** — 50 строк, которые стоят в журнале до игрока: рекорды испытуемых 01–06 и прежние сессии с датами по эре ([src/app/archive.ts](src/app/archive.ts)). Счёт у строк настоящий: сессии сыграл игрок-бот разной силы. `node scripts/archive.mjs` играет их заново и пишет `src/app/archiveData.ts`; запускать после правки темпа или очков. Архив сеанса дня каждый день свой: 50 строк из запаса в 250 сессий, по сиду дня.
- **Рекорды игрока** хранятся по виду сессии (`endless`, `timed`) и не зависят от версии правил: с новой версией журнал и лучший счёт остаются. Раньше ключ включал версию правил, и после каждой новой версии список начинался с нуля.
- **Таблицы платформы** сервер ведёт отдельно для каждой площадки (`playgama_sandbox`, `playgama`): после выхода из песочницы таблица площадки начнётся с пустой, архив в игре остаётся.
- **Подъём по местам.** После сессии её счёт поднимается по журналу: счёт и место бегут, строки проходят мимо, у своего места движение замедляется ([src/shell/climb.ts](src/shell/climb.ts)). Образец — `?lab=shell&screen=climb&score=27770`.
- **`SHARE`** копирует строку со счётом и адресом игры (`GAME_URL` в [src/platform/bridge.ts](src/platform/bridge.ts)); на телефоне открывает системное «поделиться».

## Аналитика

События уходят через `analytics.send` Bridge SDK, имена — как просит платформа (`progression_*`, `performance_sample`). Значения — только числа, строки и флаги; ничего об игроке.

| Событие | Когда | Что в нём |
|---|---|---|
| `progression_started` | начало сессии, обучения, задачи, шага обучения | `step_id`: `endless`, `timed`, `tutorial`, `task`, `tutorial_step`; для задачи — `step_index`, `level_id` |
| `progression_completed` | пройден уровень сессии (`endless_level`, `timed_level`), сеанс дня дошёл до конца, обучение пройдено, задача решена | уровень: сколько длился, сколько костей пришло и ушло, сколько стоит на поле, счёт; сессия — сводка ниже |
| `progression_failed` | поле заполнено; игрок ушёл или начал заново (`reason`: `full`, `left`, `restart`, `skipped`) | сводка сессии |
| `progression_resumed` | игрок вернулся в партию, прерванную уходом со страницы | `step_id`, сколько секунд партия уже шла |
| `session_checkpoint` | каждая целая минута сессии | минута, счёт, уровень, костей на поле, убрано, длиннейшая цепочка, секунды в опасности |
| `performance_sample` | каждые 30 секунд игры | кадры активной игры: средний FPS, перцентили времени кадра, число долгих кадров, ошибки |
| `settings_changed`, `records_opened`, `player_registered` | настройка, журнал, вход | что изменено |
| `result_shared` | игрок поделился результатом | `mode`, `score`, `how` (`sent`, `copied`, `failed`) |

Сводка сессии (по ней настраивается темп и приход костей): `rules` — ключ правил, `score`, `level`, `duration_sec`, `max_chain`, `best_chain_score`, `clears`, `removed`, `spawned`, `cubes_end`, `first_clear_sec`, `steps`, `blocked_steps`, `falls`, `ground_sec`, `floor_climbs` (подъёмы с пола на кость, которую нельзя толкнуть), `dock_descents` и `dock_climbs` (сходы с уходящей кости на клетку рядом с цепочкой и подъёмы с такой клетки на стоящую кость), `danger_sec`, `saves` (сколько раз поле уходило от опасной отметки), `chain_quiet_max_sec`, `match_2`…`match_6` (группы по числу на гранях), `ones`, `chains_2`, `chains_3`, `chains_4plus` (цепочки по длине), `contact`, `scored`, `best`. Считает [src/app/telemetry.ts](src/app/telemetry.ts).

В сводку сессии входят и показания, по которым сверяются боты ([src/rules/bot.ts](src/rules/bot.ts)): `drought_max_sec` (самое долгое ожидание очистки), `gifts` (подарки режиссёра), `clean_boards` (чистое поле), `wave` (до какой волны дошла партия). И то, что партия значит внутри визита: `run_index` (какая по счёту), `losses_in_row` (сколько партий подряд до неё кончились заполненным полем), `since_last_run_sec` (пауза после прошлой партии), `resumed` (партия продолжена после ухода со страницы), `control` (жесты или кнопки), `touch` (сенсорный экран).

Где смотреть: кабинет разработчика Playgama, раздел аналитики игры; агент читает те же данные через `get_game_telemetry_analytics`. Пока игра в статусе черновика, сводки там нет.

## Возврат в партию

Телефон выгружает страницу, которой не видно, и партия пропадала. Теперь партия Endless или сеанса дня, от которой игрок ушёл, сохраняется (`vi.run.v1`, [src/app/savedRun.ts](src/app/savedRun.ts)): когда страница скрывается или закрывается, состояние партии кладётся в хранилище платформы. При следующем запуске игра открывается на паузе этой партии. Сохранённая партия снимается, когда партия окончена, брошена или начата заново; под другой версией правил не поднимается; сеанс дня — только в свой день.

## Управление

- ПК: стрелки или WASD. ↑/W — от себя, →/D — вправо, ↓/S — к себе, ←/A — влево (с поправкой на поворот поля). Esc — пауза.
- Телефон: свайп вверх, вниз, вправо или влево — те же четыре направления, что у стрелок; удержание повторяет шаг. В панели плейтеста можно включить кнопки.

## Плейтест

Пауза → «Плейтест». Там переключатели экспериментов, выбор управления, повтор обучения и статистика последней партии, которую можно скопировать текстом. Изменения правил применяются со следующей партии; рекорды ведутся отдельно для каждого набора правил.

Два правила пола включены по умолчанию и выключаются там же по отдельности: `floorClimb` — с пола на кость, которую нельзя толкнуть, поднимаются; `dockSteps` — клетки рядом с уходящей группой работают как ступени. Обучение идёт без обоих. Спека — [docs/superpowers/specs/2026-10-03-vi-floor-and-islands-design.md](docs/superpowers/specs/2026-10-03-vi-floor-and-islands-design.md).

### Дебаг-панель

Включается в панели плейтеста («Дебаг-панель переменных») или адресом `http://localhost:5183/?debug`, открывается кнопкой ⚙ в шапке. Ползунки геймплея применяются со следующей партии (кнопка «Заново»), углы камеры — сразу. Партия с изменёнными переменными в рекорды не пишется.

### Замер производительности

`?perf` в адресе показывает в углу три строки, в любой сборке:

- кадров в секунду, 95-й процентиль и максимум промежутка между кадрами, число кадров дольше 33 мс, время кода кадра;
- переключений буфера и отрисовок на кадр, точек, залитых в видеокарту, число собранных шейдеров;
- с каким качеством нарисована страница.

Качество задаётся там же, чтобы на телефоне увидеть цену каждой части картинки: `?perf&msaa=2`.

| Параметр | Значения | Что меняет |
|---|---|---|
| `msaa` | `0`, `2`, `4` | образцы сглаживания поля; без параметра игра начинает с 4 и сама убавляет их, если устройство не держит 60 кадров (на экране 120 Гц — одну ступень, чтобы держать его частоту) |
| `auto` | `off` | игра не убавляет сглаживание сама |
| `ratio` | `0.5`–`3` (по умолчанию `1.5`) | предел точек холста на точку CSS |
| `video` | `off` | слои идут на экран без размытия, расхождения цветов, свечения и зерна |
| `leak` | `off` | за полем ничего не просачивается |
| `cap` | число, например `60` | предел кадров в секунду на экранах 90 и 120 Гц |
| `patch` | `off` | слой-холст заливается в видеокарту целиком, а не изменившейся частью: проверка на случай, если браузер кладёт часть не на место |

Без параметров картинка и поведение обычные. Настройки читает [src/display/quality.ts](src/display/quality.ts).

### Вид поля на телефоне

Где клетка всей доски была бы мельче `minCell`, поле приближено, и экран показывает ту его часть, где стоит игрок: вид идёт за игроком по доске и не выходит за её край. Поле и кости при этом ровные, как при всей доске; остальная часть доски за краем экрана. Вид и его числа задаются в адресе, в любой сборке: `?view=follow&focus=0.6&followMs=250`.

| Параметр | Значения | Что меняет |
|---|---|---|
| `view` | `auto` (по умолчанию), `full`, `follow` | `auto` — по размеру клетки, настройке CAMERA в SYSTEM и уменьшенному движению; `full` и `follow` — вид назначен, что бы ни было; `follow` из адреса берёт масштаб прямо из `focus`, чтобы вид можно было смотреть на любом экране |
| `focus` | `0.3`–`1` (по умолчанию `0.6`) | наименьшая доля доски, которая помещается в экран: клетка крупнее, чем при всей доске, не больше чем в `1 / focus` раз |
| `minCell` | `0`–`120` (по умолчанию `64`) | размер клетки при слежении, в точках CSS: слежение включается, если клетка всей доски мельче, и увеличивает её до этого размера, но не сильнее `focus` |
| `followMs` | `0`–`1000` (по умолчанию `250`) | за сколько миллисекунд вид догоняет игрока; `0` — без догона |
| `edge` | `0`–`0.5` (по умолчанию `0.1`) | на какую долю экрана игрок не подходит к его краю, стоя у края доски; столько же экрана рядом с ним остаётся пустым. `0` — пустоты за краем доски не видно никогда, `0.5` — игрок всегда в центре |
| `lens` | `0`–`1` (по умолчанию `0` — выключена) | проба: линза поверх кадра. Поле и кости рисуются как есть, ровными, а их картинка сжимается к краям экрана, чтобы в кадр вошло больше доски, чем помещается; `1` — вся доска |
| `sharp` | `0`–`1` (по умолчанию `1`) | только с линзой: какую долю увеличения слой поля возмещает плотностью. `1` — картинка у игрока резкая, как без линзы; `0` — слой не плотнее холста, мягче и дешевле для видеокарты |

Читает [src/render/params.ts](src/render/params.ts) (`readView`); те же числа — в лаборатории `?lab=board`, папка «Вид».

## Структура

| Папка | Что в ней |
|---|---|
| `src/rules` | Чистая детерминированная симуляция: шаг 20 мс, seeded PRNG, состояние — простой JSON |
| `src/app` | Игровой цикл, журнал команд, пороги контакта по счёту, удары и замирание кадра (`juice.ts`), статистика партии и пазлов, архив и журнал сеансов (`archive.ts`, `standings.ts`) |
| `src/puzzle` | Уровни пазл-режима и проверка их решений на настоящих правилах |
| `src/levels` | Уровни игры, проба из девяти (`levels.ts`): три типа на одном лупе — очистка поля, комбинация, цепочка; у уровня поле, грани, число костей, приход, цель, сид и лимит ходов. Правила уровня — в `src/rules/level.ts`; сид и лимит берутся из прогона ботов `node scripts/levels.mjs seeds=24`; открываются по адресу `?levels` |
| `src/input` | Клавиатура, жесты, логика повтора |
| `src/render` | Three.js: поле — кости в цветах каналов, стекло на подъёме и спуске, фигура, сетка, знаки открытой цепочки, искры и кольцо от группы (`burst.ts`), слой фона; кадр всей доски и кадр слежения за игроком (`framing.ts`); параметры вида в `params.ts`, цвета — из палитры оболочки |
| `src/display` | Единственный рендерер и канвас: слои со своим разрешением, вывод на экран, эффекты сигнала, линза поверх кадра «у игрока крупнее, края сжаты», выключенная проба (`lens.ts` — формула, `lensPass.ts` — её часть шейдера), PS1-материал, настройки качества (`quality.ts`) |
| `src/signal` | Передачи: кадр собирается из места (`places/`), предметов (`things/`) и отклонений (`compose.ts`), тяжелеет с контактом; распорядитель, проигрыватель окна, просачивания за полем |
| `src/shell` | Единый слой интерфейса в канвасе: boot, главное меню (шесть костей и записи), показания партии (`hud.ts`), панели (`panels.ts`: пауза, итог, журнал, настройки, задачи), белый текст прозы (`voice.ts`); набор для рисования, ввод, тексты, параметры вида |
| `src/lab` | Лаборатории: `?lab=sea_pole&variant=b&mood=fear` — сцена с панелью параметров и подписью; `?lab=shell&screen=menu` — оболочка с панелью её вида (`screen=climb&score=…` — подъём сессии по журналу, со звуком); `?lab=board` — поле с образцовым состоянием и панелью его вида; `?lab=juice` — игра с панелью, где каждый удар запускается кнопкой; `?lab=sound` — звук: кнопка на каждое событие партии и интерфейса, цепочка из N звеньев, ответ той стороны и панель параметров |
| `src/audio` | Звук, синтезированный в коде на WebAudio, без файлов и без фона: строй и ноты граней (`scale.ts`), что играть на событие правил, на удар, на действие интерфейса и на окно передачи, и когда отвечает та сторона (`score.ts`), голоса (`voices.ts`), варианты без повторов (`variation.ts`), параметры (`params.ts`), контекст, эхо и ограничитель (`engine.ts`) |
| `src/ui` | Тексты на языке игрока и инструменты разработки: панель плейтеста, статистика задач, дебаг-панель, счётчик кадров, строки замера (`perf.ts`). Интерфейса игрока здесь больше нет |
| `src/platform` | Хранилище, настройки и платформа: `bridge.ts` — единственное место, где игра говорит с Playgama Bridge SDK |
